第1章：Qlib 行情数据加载

像一个图书管理员，把散乱的股票行情数据按「股票×天数×特征」整理成整齐的书架。

欢迎

AlphaPROBE 把 alpha 挖掘建模成 DAG 上的导航，但所有这些高阶能力——贝叶斯检索、LLM 生成、知识图谱——最终都要落地到一个最朴素的问题：从哪里拿到干净的行情数据？本章带你走进 src/alphagen_qlib/stock_data.py，这是整个系统的数据源头。它把 Qlib 的行情数据库封装成一个统一的三维张量接口，让上层模块只关心「股票×天数×特征」三个维度，而不必理会 Qlib 的 DataFrame 细节。

理解这一层的关键，是看清「数据是如何从字符串表达式变成 GPU 张量的」。一旦你掌握了 StockData 的两个核心方法 _load_exprs 与 _get_data，后续章节里所有因子求值、IC 计算、贝叶斯检索都会变得顺理成章——因为它们最终都落在这套数据接口之上。AlphaPROBE 的入口 train_new_work.py 在第一行就实例化了 StockData，可见它的基础地位。

它解决什么问题？

量化研究里最折磨人的事不是写策略，而是拼数据。开盘价、收盘价、最高价、最低价、成交量、成交额，分散在不同表里；交易日历要对齐；时序算子需要回看历史窗口；标签需要未来 20 天收益。如果每个模块都自己处理这些琐事，代码会迅速变成一团乱麻。AlphaPROBE 还要在同一份行情上反复求值成千上万个LLM 生成的表达式，数据对齐哪怕错一天，IC 计算就会失真。

StockData 把这些杂事一次性收口：你只要告诉它股票池、起止日期和需要的特征，它就返回一个形状为 (n_days, n_features, n_stocks) 的 torch.Tensor，并且自动在两端预留 max_backtrack_days 和 max_future_days 的缓冲区，让时序算子和未来收益标签都有据可依。类比图书管理员：它把各种原料按统一规格切好、装袋、贴标，下游厨师（表达式求值器）拿到手就能直接下锅。

核心设计思路

设计上有三个关键取舍。第一，用 Qlib 表达式而非原始表：特征的取值不是直接读列，而是用 $close、$open 这样的表达式去 Qlib 求值，好处是同一套机制既能取原始价，也能取复权因子调整后的真实值（raw=True）。第二，张量化：所有数据最终落到 GPU 张量上，避免每次算因子时在 DataFrame 与 Tensor 之间反复转换，这对 AlphaPROBE 反复求值海量表达式至关重要。第三，缓冲区预留：用 max_backtrack_days 向前回退、max_future_days 向后延伸，保证有效区间里每一天的时序算子都能算满、未来收益标签都不越界。

我们直接读源码。先看构造器如何把参数组装成张量，再看真正落地的 _get_data 与对接 Qlib 的 _load_exprs。

代码深入

StockData.__init__ —— 把参数组装成张量接口

构造器先初始化 Qlib（用类变量保证只初始化一次），再记录 instrument、起止时间、缓冲区长度、特征列表，最后调用 _get_data 真正把张量算出来。注意第 62 行：默认特征是 list(FeatureType)，即 OPEN/CLOSE/HIGH/LOW/VOLUME/VWAP 全部六个。

stock_data.py第 42-65 行
42    def __init__(self,
43                 instrument: Union[str, List[str]],
44                 start_time: str,
45                 end_time: str,
46                 max_backtrack_days: int = 100,
47                 max_future_days: int = 30,
48                 features: Optional[List[FeatureType]] = None,
49                 device: torch.device = torch.device('cuda:0'),
50                 raw:bool = False,
51                 qlib_path:Union[str,Dict] = "",
52                 freq:str = 'day',
53                 ) -> None:
54        self._init_qlib(qlib_path)  # 初始化 Qlib，类变量保证进程内只初始化一次
55        self.df_bak = None
56        self.raw = raw  # raw=True 时走复权表达式分支
57        self._instrument = instrument
58        self.max_backtrack_days = max_backtrack_days  # max_backtrack_days 向前回退，供时序算子取历史
59        self.max_future_days = max_future_days
60        self._start_time = start_time
61        self._end_time = end_time
62        self._features = features if features is not None else list(FeatureType)  # 默认加载全部六类特征 OPEN..VWAP
63        self.device = device
64        self.freq = freq
65        self.data, self._dates, self._stock_ids = self._get_data()  # 构造期即调用 _get_data 落地 GPU 张量

第 65 行是关键：构造期就把张量算好缓存下来，之后所有 expr.evaluate(data) 都直接在这份张量上切片，避免重复加载。AlphaPROBE 的训练循环里会反复调用 pool.get_ic、pool.get_ic_icir_mutics，它们都依赖这份只读张量。

StockData._get_data —— 张量真正落地

这个方法把一组 FeatureType 枚举转成 Qlib 表达式字符串，交给 _load_exprs 求值，再把返回的 DataFrame 重排成三维张量。注意第 108 行的 stack().unstack()，它把「特征在行、股票在列」的 Qlib 默认布局翻转成我们想要的方向。

stock_data.py第 99-113 行
99    def _get_data(self) -> Tuple[torch.Tensor, pd.Index, pd.Index]:
100        features = ['$' + f.name.lower() for f in self._features]  # 把 FeatureType 枚举拼成 $close/$open 等 Qlib 表达式
101        if self.raw and self.freq == 'day':  # raw 模式把特征转成由基础量复合的复权表达式
102            features = change_to_raw(features)
103        elif self.raw:
104            features = change_to_raw_min(features)
105        df = self._load_exprs(features)  # 调用 _load_exprs 让 Qlib 求值，返回 DataFrame
106        self.df_bak = df
107        # print(df)
108        df = df.stack().unstack(level=1)  # stack/unstack 重排：把特征变行、股票变列
109        dates = df.index.levels[0]                                      # type: ignore  # dates 是交易日索引，stock_ids 是股票列名
110        stock_ids = df.columns
111        values = df.values
112        values = values.reshape((-1, len(features), values.shape[-1]))  # type: ignore  # reshape 成 (天数, 特征数, 股票数) 后转 GPU 张量
113        return torch.tensor(values, dtype=torch.float, device=self.device), dates, stock_ids

第 108 行的 df.stack().unstack(level=1) 是经典的 pandas 重排技巧。Qlib 默认返回的多层索引 DataFrame 是 (日期, 股票) × 特征，stack() 把特征列压入行索引，unstack(level=1) 再把股票提到列，最终得到 日期 × (股票×特征) 的表，再 reshape 成三维张量。这一步看似简单，却是后面所有横截面计算能向量化的前提。

n_days 属性会扣掉两端的缓冲区：第 125 行 n_days = data.shape[0] - max_backtrack_days - max_future_days。也就是说张量里前 max_backtrack_days 天和后 max_future_days 天是「垫片」，专门让 TsMean、Ref 这类算子有历史可看、让 Ref(close, -20) 这样的未来标签有未来可取，而不会在有效区间里出现 NaN。

StockData._load_exprs —— 连接 Qlib 与上层

这个方法把表达式字符串交给 Qlib 的 QlibDataLoader 求值，并按起止时间截取窗口。它要处理的麻烦事是：用户给的是字符串日期，但 Qlib 内部按日历索引寻址，所以要用 searchsorted 做映射，还要在两端扩展缓冲区。

stock_data.py第 81-97 行
81    def _load_exprs(self, exprs: Union[str, List[str]]) -> pd.DataFrame:
82        # This evaluates an expression on the data and returns the dataframe
83        # It might throw on illegal expressions like "Ref(constant, dtime)"
84        from qlib.data.dataset.loader import QlibDataLoader  # 延迟导入 QlibDataLoader 与数据接口 D，避免循环依赖
85        from qlib.data import D
86        if not isinstance(exprs, list):
87            exprs = [exprs]
88        cal: np.ndarray = D.calendar(freq=self.freq)  # 取出日历日序列，用于把字符串时间锚定到交易日索引
89        start_index = cal.searchsorted(pd.Timestamp(self._start_time))  # type: ignore  # 起始时间映射到日历索引
90        end_index = cal.searchsorted(pd.Timestamp(self._end_time))  # type: ignore
91        real_start_time = cal[start_index - self.max_backtrack_days]  # 向前回退 max_backtrack_days，为时序算子预留历史
92        if cal[end_index] != pd.Timestamp(self._end_time):
93            end_index -= 1
94        real_end_time = cal[end_index + self.max_future_days]  # 向后延伸 max_future_days，为未来收益标签预留数据
95        result =  (QlibDataLoader(config=exprs,freq=self.freq)  # type: ignore  # QlibDataLoader 按表达式批量求值并截取扩展窗口
96                .load(self._instrument, real_start_time, real_end_time))
97        return result

第 91-94 行是缓冲区的核心。real_start_time 比用户给的 start_time 早 max_backtrack_days 个交易日，real_end_time 比 end_time 晚 max_future_days 个交易日。这样 QlibDataLoader.load 返回的 DataFrame 天然带缓冲，上层调用 .data 张量时只取中间有效段即可。这种「一次加载、按需切片」的设计，让 AlphaPROBE 训练循环里完全不用再操心数据对齐。

另一个细节是第 86-87 行的 if not isinstance(exprs, list)。它允许调用方传单个字符串或列表，做了轻量适配，让 StockData 既能取一组特征，也能被 calculator 复用来对任意表达式求值——这正是第 3 章 IC 评估能复用同一套数据接口的关键。

数据流

输入：Qlib 本地二进制行情库（provider_uri）、股票池 instrument、起止时间字符串、特征枚举与缓冲区长度。内部：_load_exprs 把表达式交给 Qlib 求值得到带缓冲的 DataFrame，_get_data 用 stack/unstack 重排并 reshape 成三维张量。输出：一个 (n_days+缓冲, n_features, n_stocks) 的 GPU 张量，连同 dates / stock_ids 索引，供 Feature.evaluate、calculator、AlphaKnowledgePool 共享。

关联公式

数据层本身不涉及复杂数学，但它的张量布局决定了后续计算的口径。每个因子 $v$ 都是形状 $(T, N)$ 的张量（$T$ 天、$N$ 只股票），且按日归一化（零均值、单位方差），这是 IC 可比的前提：

$$\tilde{v}_{t,n} = \frac{v_{t,n} - \mu_t}{\sigma_t + \epsilon}$$

其中 $\mu_t, \sigma_t$ 是第 $t$ 天横截面的均值与标准差。这个归一化由基类 AlphaPool._normalize_by_day 完成，会在第 3、5、8 章反复出现。

设计权衡

为什么用 Qlib 表达式而不是直接读表？因为 raw=True 时可以把 $close 展开成 $close*$factor（复权），把 $volume 展开成 $volume/$factor/1000000，「是否复权」只是表达式拼接的开关，不必维护两套数据加载逻辑。代价是引入了对 Qlib 的强依赖，但对于量化研究而言，Qlib 已是事实标准，可接受。

小结

StockData 用「Qlib 表达式 + 缓冲区 + 张量化」三件套，把行情数据收口为 (n_days, n_features, n_stocks) 张量。_get_data 负责张量落地，_load_exprs 负责与 Qlib 对接。后续所有章节的因子求值，都建立在这个接口之上。下一章我们将看到，这套数据接口如何支撑起完整的表达式与算子体系。
