第6章：LLM 表达式生成

像一个有经验的量化研究员，读理解表达式语义后，在 topic 约束下生成 N 个不同的变异表达式。

欢迎

AlphaPROBE 的第二大核心组件——DAG-aware Factor Generator。检索器选出了 top_k 个因子，现在要把它们交给 LLM，让它在 topic 约束与进化 traces 引导下生成 N 个不同的变体表达式。本章拆解 src/utils/llm.py 的 OpenAIModel 与 src/utils/prompt.py 的提示词工程，看 AlphaPROBE 如何把「让 LLM 当量化研究员」这件事工程化——从 backoff 重试、JSON 解析容错到 prompt 的12 条校验规则。这是论文标题里「DAG-aware Factor Generator」的代码核心。

它解决什么问题？

用 LLM 生成 alpha 表达式，听起来简单（让 GPT 写个公式嘛），实则处处是坑。第一坑：格式——LLM 可能输出 close/open 而非 Div($close,$open)，或夹带 markdown 代码块标记。第二坑：合法性——算子参数个数错、用科学计数法、常量类型错（整数当浮点用）。第三坑：量纲——生成 Add($close,$volume)这样量纲不匹配的表达式。第四坑：重复——反复造出与已有因子语义相同的表达式。第五坑：API 不稳——限流、超时、返回非 JSON。

类比有经验的量化研究员：他先读理解父表达式的语义（prompt 要求 LLM 「read carefully and understand」），再在 topic 约束下（如「Price volatility」）结合进化 traces 生成 N 个不同策略的变体（横截面 vs 时序、不同统计量、简化而非堆砌）。AlphaPROBE 用 prompt 工程把这一切变成可重复的管线。

核心设计思路

设计上有五个关键点。第一，system prompt 强制 JSON：PROMPT_HEAD 明确要求「ONLY CONTAINS A JSON FORMAT」，禁止代码块标记。第二，算子定义前置：PROMPT_FEATURES_AND_OPERATORS 把所有可用算子、特征、常量规则列清楚，并在 prompt 里同步量纲定义，让 LLM 自检 dimensionless。第三，进化 traces 注入：PROMPT_GENERARTION 接收 topic、父表达式、explanations、traces，让 LLM 学习历史优化方向。第四，双重容错：backoff 指数重试 + retrying 装饰器应对 API 限流，正则兜底解析非标准 JSON。第五，N 个不同策略：要求生成 generate_num 个语义不同的表达式，强制多样性。

数据流

输入：检索器选出的父表达式、topic、description、进化 traces（path_to_root 拼成）。内部：PROMPT_FEATURES_AND_OPERATORS + PROMPT_GENERARTION 拼成完整 user_prompt，OpenAIModel.chat_generate 经 backoff 重试调 API，返回 JSON 文本，正则兜底解析。输出：generate_num 个新表达式字符串及对应 explanations，送第 7 章训练循环做验证与入池。

关联公式

LLM 生成本质是条件采样，可形式化为：

$$P(e_1, \ldots, e_N \mid e_{\text{parent}}, \text{topic}, \text{traces}) = \prod_{i=1}^{N} P_{\text{LLM}}(e_i \mid e_{\text{parent}}, \text{topic}, \text{traces}, \text{prompt}))$$

其中 $N$ 是 generate_num，prompt 含算子定义与 12 条校验规则作约束。temperature $T$（默认 0.5）控制采样的尖锐度：$T$ 越低越倾向于高概率（保守）表达式，$T$ 越高越多样但越容易非法。traces 注入让 $P_{\text{LLM}}$ 成为「有偏」分布——偏向历史有效的进化方向。

设计权衡

为什么用 JSON 而非自由文本输出？因为 JSON 可被 json.loads 确定性解析，能批量校验 expressions_fixed 数量、提取 explanations。自由文本需要复杂正则，且无法保证结构完整。代价是 LLM 偶尔会输出带代码块标记的 JSON，需正则兜底（第 548 行）。为什么不直接让 LLM 输出 AST？因为 LLM 对自然语言式表达式更熟练，AST 反而增加出错率。

小结

LLM 生成用「system+user 双提示 + 算子定义 + traces 注入 + 12 条校验 + 双重重试 + JSON 兜底」把「让 LLM 当量化研究员」工程化为可重复管线。OpenAIModel 负责鲁棒调用，prompt 负责约束与引导。下一章看训练主循环如何把检索与生成串成闭环。
