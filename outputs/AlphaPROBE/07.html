第7章：训练主循环

像一个闭环工厂：检索原料(因子) → 加工(LLM 变异) → 质检(验证+IC) → 入库(进池) → 记录(日志)。

本章概览

训练主循环是 AlphaPROBE 的「心脏」，把数据接口、表达式体系、IC 评估、知识图谱、贝叶斯检索器、LLM 生成器串成一条闭环流水线 AlphaKnowledgeTrainer._train_one_iteration。输入：初始 29 表达式、StockData（训练+测试）、target、全部超参。闭环：search 选因子 → path_to_root 拼 traces → chat_generate 生成 → parse + 多窗口搜索 + 算 IC/ICIR/MutIC → try_new_expr 双路径入池 → graph.insert 更新图谱 → logger.log 写 pool_*.json + res.txt。输出：不断增长的因子池与图谱，以及每轮的测试 IC/ICIR 日志。最终池送第 9 章 Mega-Alpha 组合。

为什么需要闭环？因为 alpha 挖掘的核心矛盾是「探索 vs 利用」：探索新方向浪费算力，只利用已知好因子又陷入局部最优。闭环让变体入池后更新图谱，下一轮检索器利用更新后的 depth/times/icir 做更优选择，搜索方向不断自我修正。

核心设计思路

设计上有五个关键点。第一，检索→生成→验证→入池→日志五步闭环：search 选因子，chat_generate 生成，parser.parse + IC 评估验证，try_new_expr 入池，logger.log 记录。第二，双路径入池判定：ICIR 超越父因子直接入池；否则若 MutIC 显著降低且 ICIR 不低于父的 icir_decay_threshold，也入池（鼓励多样性贡献）。第三，多窗口搜索：含 %d 的表达式在 [5,10,20,30] 窗口暴力搜索最优。第四，已存在表达式复用：图谱里已有的表达式直接复用节点，不重复生成。第五，定时日志：每 log_freq 轮记录池状态与测试 IC。

数据流

输入：初始 29 表达式、StockData（训练+测试）、target、全部超参。闭环：search 选因子 → path_to_root 拼 traces → chat_generate 生成 → parse + 多窗口搜索 + 算 IC/ICIR/MutIC → try_new_expr 双路径入池 → graph.insert 更新图谱 → logger.log 写 pool_*.json + res.txt。输出：不断增长的因子池与图谱，以及每轮的测试 IC/ICIR 日志。最终池送第 9 章 Mega-Alpha 组合。

关联公式

双路径入池判定可形式化为两个条件，满足其一即入池：

$$\text{Path 1: } |\text{ICIR}_{\text{new}}| > |\text{ICIR}_{\text{parent}}| \;\text{and}\; |\text{IC}_{\text{new}}| > \tau_{\text{ic}}$$
$$\text{Path 2: } \max|\text{MutIC}_{\text{new}}| < \tau_{\text{new}} \;\text{and}\; |\text{IC}_{\text{new}}| > \tau_{\text{ic}} \;\text{and}\; |\text{ICIR}_{\text{new}}| > \gamma \cdot |\text{ICIR}_{\text{parent}}|$$

其中 $\tau_{\text{ic}}$ 是 ic_threshold（默认 0.006），$\tau_{\text{new}}$ 是 ic_new_threshold（默认 0.45），$\gamma$ 是 icir_decay_threshold（默认 0.7）。路径二让「预测力略降但独立性高」的因子入池，这是 AlphaPROBE 多样性保障的关键。

设计权衡

为什么允许 ICIR 略低的因子入池（路径二）？因为 Mega-Alpha 组合（第 9 章）用线性回归融合因子，因子间的低相关性比单因子高 ICIR 更重要——一个 ICIR 平平但与所有池内因子不相关的因子，能显著降低组合方差。路径二用 icir_decay_threshold=0.7 设下限，防止完全无效的因子混入，平衡了「多样性」与「质量」。

小结

训练主循环用「检索→生成→验证→入池→日志」五步闭环，把贝叶斯检索与 LLM 生成串成自我进化的管线。双路径入池判定兼顾质量与多样性，多窗口搜索让 LLM 不必猜最优窗口。下一章我们更细致地看入池前的验证流程。
