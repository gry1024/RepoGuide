第4章：表达式知识图谱

像家族族谱，每个表达式是节点，父节点是它的「前身」，子节点是它的「变体」，记录了 alpha 的进化血脉。

欢迎

进入核心层。AlphaPROBE 区别于传统 alpha 挖掘的最大特点，是把每个表达式都当作 DAG 上的一个节点，记录它的「父节点」（前身）与「子节点」（变体）。这样 LLM 生成的不是孤立的字符串，而是有血缘的家族成员。本章拆解 src/alphagen/data/expression_knowledge_graph.py，看 ExpressionKnowledgeGraph 如何构建 DAG、ExpressionNode 如何承载进化信息、path_to_root 如何追溯一条进化路径。这是第 5 章贝叶斯检索器 depth/times 衰减的数据基础。

它解决什么问题？

传统 LLM 生成 alpha 的痛点是「无记忆」：每次生成都从零开始，容易反复造出相似的因子，也无法利用「哪些变异方向曾带来增益」的历史经验。AlphaPROBE 用知识图谱解决这个问题：每个新表达式入图时记录父节点，节点上保存 IC/ICIR、topic、description、depth、times 等元数据。这样检索器就能回答「这个因子是第几代变异」「它被选中的次数」「它的子代是否比它更优」——这些信息让 LLM 生成不再是盲目的随机搜索，而是有方向的有偏进化。

类比家族族谱：每个表达式是节点，父节点是它的「前身」，子节点是它的「变体」。path_to_root 能从任一节点回溯到根，这条路径就是 alpha 的进化血脉。LLM 在生成时会拿到这条血脉（traces），学习「前人是怎么一步步优化的」，从而生成更高质量的变体。

核心设计思路

设计上有四个关键点。第一，ExpressionPayload 不可变：用 frozen dataclass 封装表达式对象、token 序列、长度、源字符串，保证节点身份稳定（按 source 字符串去重）。第二，DAG 而非树：节点用 parent 指针 + children 集合，允许一个节点有多个子节点（一个父因子可派生多个变体），但每个子节点只有一个父（单亲谱系，便于追溯）。第三，depth 与 times 双计数：depth 是谱系深度（变异代数），times 是被检索选中的次数。第 5 章检索器用 (1-depth_decay)^depth 与 (1-times_decay)^times 做双衰减，既鼓励探索深层新因子，又避免反复压榨同一老因子。第四，token 化节点身份：_tokenize 把表达式拆成 OP:Add, DT:10, FEATURE:CLOSE 这样的 token 序列，既用于计算长度（length 限制），也便于编辑距离等结构相似度计算。

build_expression_node 与 insert —— 构建节点并接入 DAG

build_expression_node 先检查表达式是否已存在，再 _build_payload 解析+tokenize，超过长度阈值的直接拒绝。insert 把节点记入 _node_records，并建立父子双向链接与 depth 传递。

152    def build_expression_node(self, expression: str, topic: str, explanation: str, length_threshold: int, ic: float = None, icir: float = None) -> Optional[ExpressionNode]:
153        if self.search(expression.strip()) is not None:  # 先查重，已存在则直接返回已有节点

191    def insert(self, expression_node: ExpressionNode, parent_node: Optional[ExpressionNode]) -> bool:
192        if self.search(expression_node.payload.source) is not None:  # 已存在则不重复插入
193            print(f"Expression {expression_node.payload.source} already exists in the graph, not inserting.")
194            return False
195        if parent_node is not None:  # 有父节点时建立双向链接
196            expression_node.parent = parent_node
197            parent_node.children.add(expression_node.payload.source)  # 父节点的 children 集合加入新节点 source
198            expression_node.depth = parent_node.depth + 1  # 新节点 depth = 父节点 depth + 1
199        self._node_records[expression_node.payload.source] = expression_node  # 记入 _node_records 供 search/path_to_root 查找
200        return True

第 198 行的 expression_node.depth = parent_node.depth + 1 是谱系深度的传递规则。初始表达式（train_new_work.py 的 29 个）以 parent_node=None 入图，depth=0；它们的 LLM 变体 depth=1，再变异 depth=2……train_new_work.py:92 的 depth_limit=7 限制了最大变异代数，防止谱系无限膨胀。insert 只记入 _node_records，不强制 size 计数，这让图谱可以容纳比池容量更多的历史节点（池淘汰的因子仍留在图谱里供追溯）。

path_to_root —— 追溯进化血脉

从任一节点沿 parent 指针回溯到根，反转后得到从最早祖先到当前节点的进化路径。这条路径会被拼成 traces 字符串喂给 LLM。

167        return self._nodes.get(expression.strip())

169    def path_to_root(self, node: ExpressionNode) -> List[ExpressionNode]:  # search 按 source 字符串查节点
170        path = []  # 从当前节点沿 parent 回溯
171        current = node
172        while current is not None:
173            path.append(current)  # 收集路径上的每个节点
174            current = current.parent  # current 上移到父节点
175        path.reverse()  # 反转：从最早祖先到当前节点
176        return path

这条路径在 alpha_knowledge_trainer.py:536 被取出，build_traces（515-524 行）把它拼成 Expression: Explanation: -> Expression: ... 的字符串，塞进 PROMPT_GENERARTION 的 traces 字段。LLM 据此学习「这个因子家族过去是怎么从简单到复杂、从弱到强演化的」，从而生成符合进化方向的变体。这正是 AlphaPROBE 论文标题里「On-graph Biased Evolution」的代码体现。

_tokenize —— 节点结构指纹

tokenize 按算子类型把表达式递归拆成 OP/DT/FEATURE/CONST token 序列。它既用于算 length（限制表达式复杂度），也供编辑距离等结构相似度计算。

expression_knowledge_graph.py第 239-263 行
239    def _tokenize(self, expr: Expression) -> Tuple[str, ...]:
240        if isinstance(expr, Feature):  # Feature 叶子 -> FEATURE:CLOSE
241            return (f"FEATURE:{expr._feature.name}",)  # type: ignore[attr-defined]
242        if isinstance(expr, Constant):  # Constant 叶子 -> CONST:1.0
243            return (f"CONST:{self._format_constant(expr._value)}",)  # type: ignore[attr-defined]
244        if isinstance(expr, _UNARY_OPERATORS):  # 一元算子 -> OP:Abs + 子树 token
245            operand = getattr(expr, "_operand")
246            return (f"OP:{type(expr).__name__}",) + self._tokenize(operand)
247        if isinstance(expr, _BINARY_OPERATORS):  # 二元算子 -> OP:Add + 左右子树 token
248            lhs = getattr(expr, "_lhs")
249            rhs = getattr(expr, "_rhs")
250            return (f"OP:{type(expr).__name__}",) + self._tokenize(lhs) + self._tokenize(rhs)
251        if isinstance(expr, _ROLLING_OPERATORS):  # 滚动算子 -> OP:TsMean + DT:10 + 子树
252            operand = getattr(expr, "_operand")
253            delta = getattr(expr, "_delta_time")
254            return (f"OP:{type(expr).__name__}", f"DT:{delta}") + self._tokenize(operand)
255        if isinstance(expr, _PAIR_ROLLING_OPERATORS):  # 成对滚动 -> OP:TsCorr + DT + 左右子树
256            lhs = getattr(expr, "_lhs")
257            rhs = getattr(expr, "_rhs")
258            delta = getattr(expr, "_delta_time")
259            return (
260                f"OP:{type(expr).__name__}",
261                f"DT:{delta}",
262            ) + self._tokenize(lhs) + self._tokenize(rhs)
263        raise TypeError(f"Unsupported expression type for tokenization: {type(expr).__name__}")

token 序列是表达式的「结构指纹」。第 5 章检索器在 use_edit_distance=True 时，会用 expression_edit_distance 算两个表达式 token 序列的编辑距离，作为多样性度量之一。length 字段则直接来自 len(tokens)，在 build_expression_node 里与 max_length 比较，拒绝过长（过复杂）的表达式——AlphaPROBE 偏好简洁可解释的因子。

数据流

输入：表达式字符串、topic、description、IC/ICIR、父节点。内部：_build_payload 解析+tokenize，build_expression_node 校验长度并构造节点，insert 建立父子链接与 depth。输出：一个接入 DAG 的 ExpressionNode，可被 search/path_to_root 查询，供检索器读取 depth/times/icir，供 LLM 读取进化 traces。

关联公式

图谱本身是数据结构，但 depth/times 直接驱动第 5 章的衰减公式：

$$\text{depth\_decay}(d) = (1 - \alpha)^{d},\quad \text{times\_decay}(k) = (1 - \beta)^{\max(k - k_0, 0)}$$

其中 $\alpha$ 是 depth_decay（默认 0.05），$\beta$ 是 times_decay（默认 0.10），$k_0$ 是 start_times（默认 2，前两次选中不衰减）。depth 越大衰减越强（鼓励回到浅层探索新方向），times 越大衰减越强（避免反复压榨同一因子）。

设计权衡

为什么用 DAG 而非树？因为一个父因子可以派生多个子因子（多变异策略），但每个子因子只记录一个父（单亲谱系）。这样 path_to_root 是唯一确定的线性路径，便于喂给 LLM 作 traces。若允许多父，路径会变成 DAG 上的多源最短路径问题，traces 失去线性叙事性，LLM 难以理解。代价是丢失了「多个父因子交叉组合」的信息，但 AlphaPROBE 用 LLM 的组合能力弥补了这一点。

小结

表达式知识图谱用「不可变 payload + 单亲谱系 + depth/times 双计数 + token 指纹」四件套，把 alpha 挖掘建模为 DAG 上的导航。insert 建立父子链接，path_to_root 追溯进化血脉，_tokenize 生成结构指纹。下一章我们看贝叶斯检索器如何利用这些元数据选出最值得进化的因子。
