AlphaPROBE 深度代码教程

AlphaPROBE：基于 DAG 偏置进化的 alpha 挖掘

Alpha Mining Via Principled Retrieval and On-graph Biased Evolution —— 用贝叶斯检索器与 DAG 感知 LLM 生成器，把 alpha 挖掘建模为 DAG 上的有方向进化。

论文概览

AlphaPROBE（Alpha Mining Via Principled Retrieval and On-graph Biased Evolution）把 alpha 挖掘重新建模为「在表达式 DAG 上的策略性导航」。它由两大核心组件构成：贝叶斯因子检索器（Bayesian Factor Retriever）综合 ICIR 质量分、depth/times 衰减、三策略多样性选 out top_k 个最值得进化的因子；DAG 感知因子生成器（DAG-aware Factor Generator）用 LLM 在父因子的进化 traces 引导下生成 N 个语义不同的变体。两者闭环运行，让搜索方向不断自我修正，最终产出的因子池用滚动 OLS 组合成 Mega-Alpha 预测。

本教程逐行拆解 AlphaPROBE 的真实代码，按「数据层 → 核心层 → 应用层」三层架构组织 10 章内容，每章都包含代码卡片（带行号与中文注释）、数据流分析、关联公式与设计权衡。目标是让你不仅能看懂 AlphaPROBE 怎么用，更能理解每个设计决策背后的「为什么」。

端到端数据流

从行情数据到 Mega-Alpha 预测的完整数据流：

# 1. 数据层：Qlib 行情 → GPU 张量 Qlib binary data └─ StockData._load_exprs (src/alphagen_qlib/stock_data.py) └─ StockData._get_data → (n_days, n_features, n_stocks) Tensor # 2. 核心层：DAG 上的闭环进化 初始 29 表达式 (train_new_work.py:21) └─ AlphaKnowledgeTrainer.train (alpha_knowledge_trainer.py) ├─ [检索] pool.search → top_k 个 ExpressionNode │ ├─ ICIR sigmoid 归一化 (alpha_pool.py:148) │ ├─ depth/times 双衰减 (alpha_pool.py:152-153) │ └─ leaf: 三策略多样性 / non_leaf: 子代增益×稀疏度 ├─ [生成] graph.path_to_root → traces │ └─ model.chat_generate (PROMPT_GENERARTION + 算子定义) │ └─ JSON 解析兜底 → N 个新表达式 ├─ [验证] parser.parse 语法校验 │ └─ pool._calc_ics_and_icir → IC/ICIR/MutIC ├─ [入池] pool.try_new_expr 双路径判定 │ ├─ 路径一: ICIR 超越父因子 │ └─ 路径二: MutIC 显著降低 且 ICIR ≥ 父×0.7 └─ [日志] logger.log → pool_*.json + res.txt # 3. 应用层：Mega-Alpha 动态组合 pool_*.json (表达式列表) └─ run_adaptive_combination.run (run_adaptive_combination.py) ├─ 预计算逐日 IC/RankIC 张量 ├─ 滚动循环 (每天): │ ├─ 双阈值筛因子 (threshold_ric / threshold_ricir) │ ├─ remove_linearly_dependent_cols 去共线性 │ └─ torch.linalg.lstsq OLS 回归 → 当天预测 └─ 输出: valid/test IC/ICIR/夏普/最大回撤 + ret_s.npy

阅读路径

线性阅读：从第 1 章数据层开始，逐章深入到第 10 章 baseline 对比，适合想完整理解 AlphaPROBE 的读者。每章末尾的「小结」会预告下一章主题。

按兴趣跳读：如果你关心 LLM 如何生成表达式，直接看第 6 章；如果你关心检索器如何选因子，看第 5 章；如果你关心最终预测如何生成，看第 9 章。每章都自包含必要的背景说明。

代码实践：本教程所有代码卡片都标注了真实文件路径与行号，建议打开 _repoguide_probe/repo/ 源码对照阅读，并结合 train_new_work.py 与 run_adaptive_combination.py 两个入口脚本实际跑通管线。
