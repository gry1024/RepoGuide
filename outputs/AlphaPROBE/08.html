第8章：表达式验证与入池

像机场安检，新表达式要过「语法合法」「量纲为零」「IC 达标」「与池内因子互相关不超标」四道关。

本章概览

验证与入池是保证池质量与多样性的最后一道闸门。本章拆解 AlphaKnowledgePool.try_new_expr 与 ExpressionParser.parse。输入：LLM 生成的表达式字符串（或 Expression 对象）、topic、description、图谱节点。验证：parser.parse 语法校验 → expr.evaluate 求值 → _calc_ics_and_icir 算 IC/ICIR/MutIC → ic_mut_threshold 防重复 → 池满时与最低 IC 比较。输出：True（入池）或 False（拒绝）。入池则更新 exprs/values/icir/mutual_ics 及 topic/description/node，并触发 _pop 末位淘汰。

为什么需要四道关？因为 LLM 即使有 12 条校验规则，仍可能输出非法语法（如 Add(x) 参数不足）、量纲不为零（如 Add($close,$volume)）、IC 过低（噪声因子）、或与池内因子高度重复（Rank($close) 与 Rank(Rank($close)) 语义等价）。任一关不通过都被拒绝，只有四关全过且（池满时）优于池内最差因子才能入池。

核心设计思路

设计上有四个关键点。第一，解析即校验：ExpressionParser.parse 在组装表达式树时每步都 validate，非法结构立刻抛 InvalidExpressionException。第二，量纲零约束：虽然 try_new_expr 本身不显式调 DimensionCalculator，但 prompt 已强制 LLM 生成 dimensionless 表达式，解析器间接保证（非法量纲的表达式多会在求值时出错）。第三，IC + MutIC 双阈值：IC 绝对值要超 ic_threshold（第 7 章路径判定），MutIC 最大值要不超过 ic_mut_threshold（防重复）。第四，池满则末位淘汰：池满时新因子必须优于池内 IC 最低的因子，入池后 pop 掉最差因子。

第 53-77 行的 validate 是语法校验的核心。它保证算子的参数契约：UnaryOperator 的操作数必须含 Feature（不能对纯常量取 Abs）；RollingOperator 栈顶必须是 DeltaTime（TsMean($close, 10) 里的 10）；PairRollingOperator 需要两个 featured 操作数 + DT。这些校验在 token 入栈时即时进行，LLM 输出的 Add(x)（参数不足）或 TsMean($close)（缺窗口）都会立刻抛 InvalidExpressionException。第 39 行的 is_valid 进一步要求最终栈中只剩一棵含 Feature 的树——纯常量表达式（如 Add(1.0, 2.0)）会被拒绝。

try_new_expr —— IC 与互相关双阈值

解析通过后，try_new_expr 算 IC/ICIR/MutIC，按 ic_mut_threshold 防重复，池满时与最低 IC 因子比较决定是否淘汰。

_pop 与 _swap_idx —— 末位淘汰与交换

_pop 找 IC 最低的因子与池末尾交换并截断 size。_swap_idx 在交换因子时同步交换所有元数据。

404    def _pop(self) -> None:
405        # Pop the factor with the lowest ic
406        if self.size <= self.capacity:  # size 未超 capacity 则不淘汰
407            return
408        idx = np.argmin(self.single_ics[:self.size])  # 找 IC 绝对值最低的因子索引
409        self._swap_idx(idx, self.capacity)  # 把它换到 capacity 位置
410        self.size = self.capacity  # 截断 size 到 capacity

412    def _swap_idx(self, i, j) -> None:  # _swap_idx 交换两个因子
413        if i == j:
414            return
415        # Call parent method to handle standard factor swapping
416        super()._swap_idx(i, j)  # 调父类交换 exprs/values/ics
417        # Swap embeddings
418        self.topics[i], self.topics[j] = self.topics[j], self.topics[i]  # 同步交换 topics/descriptions
419        self.descriptions[i], self.descriptions[j] = self.descriptions[j], self.descriptions[i]

第 416-420 行的同步交换是关键：交换两个因子时，不仅交换父类的 exprs/values/single_ics/mutual_ics，还要交换 AlphaPROBE 特有的 topics/descriptions/expr2node/icir。如果漏掉任一字段，检索器会读到错位的元数据（如用 A 因子的 icir 配 B 因子的 description），导致打分失真。这种「扩展字段必须同步交换」是继承式扩展的典型负担，但保证了元数据与因子的一致性。

数据流

输入：LLM 生成的表达式字符串（或 Expression 对象）、topic、description、图谱节点。验证：parser.parse 语法校验 → expr.evaluate 求值 → _calc_ics_and_icir 算 IC/ICIR/MutIC → ic_mut_threshold 防重复 → 池满时与最低 IC 比较。输出：True（入池）或 False（拒绝）。入池则更新 exprs/values/icir/mutual_ics 及 topic/description/node，并触发 _pop 末位淘汰。

关联公式

入池判定（池未满时）的核心是互相关阈值：

$$\text{accept} \iff \max_{j \in \text{pool}} |\text{MutIC}_{\text{new}, j}| \leq \tau_{\text{mut}}$$

池满时额外要求（末位淘汰）：

$$\text{accept} \iff |\text{IC}_{\text{new}}| > \min_{j \in \text{pool}} |\text{IC}_j| \;\text{and}\; \max_{j} |\text{MutIC}_{\text{new}, j}| \leq \tau_{\text{mut}}$$

其中 $\tau_{\text{mut}}$ 是 ic_mut_threshold（默认 0.9）。MutIC 是新因子与池内因子的逐日 Pearson IC 均值（第 3 章 _calc_ics_and_icir 第 234 行）。这个阈值防止「语义等价」的因子重复占池，是池多样性的硬保障。

设计权衡

为什么 ic_mut_threshold 设 0.9 这么高？因为 AlphaPROBE 还有第 5 章的贝叶斯检索器做软性多样性引导，入池判定只做硬性防重复。0.9 允许「相关但不完全等价」的因子共存（如 TsMean($close,5) 与 TsMean($close,10)），它们在某些时段可能互补。若阈值设太低（如 0.5），池会过度稀疏，无法支撑 Mega-Alpha 组合所需的因子数量。

小结

表达式验证与入池用「parser 语法校验 + IC/MutIC 双阈值 + 末位淘汰」四道关，保证池内每个因子都合法、有效、不重复。try_new_expr 是入口，_add_factor 写入元数据，_pop/_swap_idx 维护池容量。下一章看池中因子如何被组合成 Mega-Alpha 预测。
