第5章：贝叶斯因子检索器

像选秀节目的评委，综合「实力(ICIR)」「新鲜度(depth/times decay)」「多样性(互相关/语义/编辑距离)」打分，选出最值得进化的选手。

本章概览

贝叶斯因子检索器是 AlphaPROBE 两大核心组件之一，每轮迭代从知识图谱里挑出 top_k 个最值得进化的因子送 LLM。本章逐行拆解 AlphaKnowledgePool.search 方法。输入：池内因子的 ICIR、图谱节点的 depth/times、mutual_ics 互相关矩阵、description/topic 文本、表达式 token。中间：ICIR 经 sigmoid 归一化，乘 depth/times 衰减得 quality_prob；叶子算三策略多样性，非叶子算子代增益×稀疏度；二者相乘得最终 score。输出：top_k 个 ExpressionNode 及对应表达式，供训练循环调用 LLM 生成；被选中节点的 times 递增。

检索的三大矛盾：实力 vs 新鲜度（老因子已被压榨、新因子可能蕴含新方向）；实力 vs 多样性（只挑 ICIR 最高会让子代同质化）；叶子 vs 非叶子（叶子未探索、非叶子有进化数据）。AlphaPROBE 用乘法打分综合三维度，再用 leaf/non_leaf 分组保证两类节点都被选中。

核心设计思路

设计上有五个关键点。第一，ICIR 质量分经 sigmoid 归一化：先把 icir 标准化再过 stable_sigmoid，映射到 (0,1)，避免量纲差异。第二，双衰减乘子：quality_prob = icir_logit * depth_decay * times_decay，乘法让衰减直接压低被过度开发的因子。第三，叶子用三策略多样性：残差相关(1-mean_corr)、语义相似度(1-mean_sim)、编辑距离(mean_edit)，三者相乘得 pool_quality。第四，非叶子用子代增益 + 稀疏度：子代 ICIR 相对父代的增益（鼓励产出优秀子代的父），乘以父子/子子相关的稀疏度（鼓励产出差异化子代的父）。第五，leaf/non_leaf 分组选 top_k：各取一半 top_k，保证探索与利用平衡。

search 主干 —— 质量分与衰减

这是检索器的入口。先收集所有有图谱节点的池内因子，算 ICIR 质量分，再乘 depth/times 衰减，得到 quality_prob。

第 148 行的 stable_sigmoid((icir_raw - mean_icir)/(std_icir+1e-6)) 是贝叶斯式打分的关键：它把 ICIR 标准化后压到 (0,1)，让不同量级的 ICIR 可比。第 152-153 行的双衰减是「新鲜度」核心：depth 大的深层因子衰减强（鼓励回浅层探索新方向），times 大的因子衰减强（避免反复压榨）。注意第 153 行的 np.maximum(times - start_times, 0)——前 start_times 次选中不衰减，给新因子足够的探索机会。三者相乘得 quality_prob，这就是「实力×新鲜度」的综合分。

compute_leaf_quality —— 叶子节点的三策略多样性

叶子节点（无子代）用三策略算多样性分：残差相关、语义相似度、编辑距离，三者相乘。每策略都是「1 - 与其他候选的平均相似度」，越独特分越高。

216        def compute_leaf_quality(pos: int) -> float:

229                    semantic_score = clip_prob(1.0 - float(mapped))

231            if edit_matrix is not None:
232                others = [j for j in range(num_nodes) if j != pos]
233                if others:
234                    edit_score = clip_prob(float(edit_matrix[pos, others].mean()))  # edit_score = 平均编辑距离比例
235            return clip_prob(corr_score * semantic_score * edit_score)  # 三策略相乘得叶子多样性分

第 218-222 行的残差相关用 mutual_ics 矩阵（第 3 章算的互相关），1 减去与其他候选的平均绝对相关，越独特分越高。第 224-229 行的语义相似度用 SentenceTransformer（默认 Qwen3-Embedding-4B）编码 description/topic，算余弦相似——这能捕获「表达式不同但语义相同」的重复，比如 Rank($close) 和 Rank(Rank($close))。第 230-234 行的编辑距离用 token 序列的结构差异。三者相乘（第 235 行）让任一维度高相似都会压低分数，保证选出的因子在数值、语义、结构三方面都足够多样。

compute_non_leaf_quality —— 非叶子节点的子代增益与稀疏度

非叶子节点（有子代）评估「进化价值」：子代 ICIR 相对父代的增益 × 父子/子子相关的稀疏度。增益高说明这个父因子善于产出优秀子代，稀疏度高说明它的子代彼此差异化。

第 257-259 行的子代增益是 AlphaPROBE 的创新点：它不直接看父因子本身的 ICIR，而看「这个父因子历史上产出的子代，相对它有多少 ICIR 提升」。一个自身 ICIR 平平但善于产出优秀子代的因子，会被赋予高分——因为它「进化潜力大」。第 292 行的稀疏度 1 - parent_child_avg * child_child_avg 进一步要求子代之间也要差异化：如果某父因子的子代都高度相似，说明它的变异空间已枯竭，应降低优先级。这种「以子代质量评估父代价值」的思路，正是 on-graph biased evolution 的精髓。

数据流

输入：池内因子的 ICIR（池缓存或节点 icir）、图谱节点的 depth/times、mutual_ics 互相关矩阵、description/topic 文本、表达式 token。内部：ICIR 经 sigmoid 归一化，乘 depth/times 衰减得 quality_prob；叶子算三策略多样性，非叶子算子代增益×稀疏度；二者相乘得最终 score。输出：top_k 个 ExpressionNode 及对应表达式，供第 7 章训练循环调用 LLM 生成；被选中节点的 times 递增。

关联公式

检索器的综合打分是各因子的乘积：

$$\text{score}_i = \underbrace{\sigma(\tilde{\text{ICIR}}_i) \cdot (1-\alpha)^{d_i} \cdot (1-\beta)^{\max(k_i-k_0,0)}}_{\text{quality\_prob}} \cdot \underbrace{Q_i^{\text{pool}}}_{\text{多样性/进化价值}}$$

其中 $\sigma$ 是 sigmoid，$\tilde{\text{ICIR}}$ 是标准化后的 ICIR，$Q_i^{\text{pool}}$ 对叶子是 (1-mean_corr)(1-mean_sim)(mean_edit)，对非叶子是 mean_gain × (1 - parent_child_corr × child_child_corr)。代码第 316 行 scores = quality_prob * pool_quality 正对应这个公式。

设计权衡

为什么用乘法而非加法融合三维度？因为乘法让任一维度的低分都会显著压低总分——一个 ICIR 极高但与池内因子完全重复的因子，乘法会让它的多样性分≈0，从而被淘汰；加法却可能让高分 ICIR 掩盖低多样性。代价是对极端值敏感，故每项都用 clip_prob 压到 [1e-6, 1-1e-6]，避免乘出 0 或溢出。这种「短板效应」正是贝叶斯检索要的：综合最均衡的因子才值得进化。

小结

贝叶斯检索器用「ICIR 质量分 × depth/times 双衰减 × 三策略多样性/子代增益」三维度乘法打分，再用 leaf/non_leaf 分组保证探索与利用平衡，选出 top_k 个因子送 LLM 进化。这是 AlphaPROBE「Principled Retrieval」的代码核心。下一章看 LLM 如何在这些因子上生成变体。
