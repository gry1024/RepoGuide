第 10 章：Baseline 对比

PPO、QCM、AFF 三类基线 —— 与 GFlowNet 同台竞技的对照组

欢迎

欢迎来到第 10 章！这是本教程的最后一章。前面九章我们讲了 AlphaSAGE 的各个组件，但要证明“GFlowNet + RGCN + 多维奖励”这套组合有效，就得与其他方法同台竞技。AlphaSAGE 仓库提供了三类基线：PPO（传统 RL）、QCM（分位式 RL）、AFF（融合组合基线）。本章会依次读它们的入口脚本，看它们与 GFlowNet 共享哪些接口、又在哪里分道扬镳。

本章会进入 train_ppo.py、train_qcm.py、combine_AFF.py，看它们如何复用 StockData、AlphaPool、AlphaEnv，以及各自的策略估计与组合逻辑。

它解决什么问题？

类比来说，Baseline 对比像同场竞技的对照组，PPO、QCM、AFF 各显神通，用以衡量 GFlowNet 的优势。

研究项目需要“对比实验”才能证明方法的优越性。AlphaSAGE 提出了“GFlowNet + RGCN + 多维奖励”这一套新方法，需要与传统 RL（PPO）、分位式 RL（QCM）、融合组合（AFF）对照，才能说明“多样化生成”与“结构感知”的价值。这些基线复用了 AlphaSAGE 的数据与池接口，保证了“同起点”的公平性。

核心设计思路

Baseline 的设计思路是共享接口 + 差异化策略 + 同框架评估。

共享接口：所有基线都使用同一个 StockData、同一个 target（Ref(close, -20) / close - 1）、同一个 AlphaPool、同一个 AlphaEnv。这让对比只反映“策略不同”的影响，排除了数据与环境的差异。

差异化策略：PPO 用 MaskablePPO 训练 LSTM 策略；QCM 用 QR-DQN/IQN/FQF 估计 Q 值分位；AFF 用 GAN 生成 alpha 并加权融合。它们在“怎么生成 alpha”上各有侧重。

同框架评估：所有基线都用第 9 章的 get_tensor_metrics 计算 IC、ICIR、夏普、MDD，输出可比指标。这让对比结果公平、可复现。

看 PPO 入口。第 96-104 行是共享部分：设备、target、数据加载都与 GFlowNet 一致。这保证了同起点。

第 123-128 行创建 AlphaPool（不是 AlphaPoolGFN）。这里只用了父类，没有 SSL 与新颖度逻辑，反映了 PPO “只看 IC”的简单策略。

第 129 行创建 AlphaEnv。这个环境与 GFlowNet 的 GFNEnvCore 共享同一个 AlphaPool 实例，但接口不同：PPO 调用 step(action)，而 GFlowNet 调用 reward(state)。

第 139-149 行创建 CustomCallback，定期在测试集上评估、保存 checkpoint。这个 callback 会调用 pool.test_ensemble(test_data, target)，计算 IC 与 rIC，是与 GFlowNet 同框架评估的体现。

第 151-169 行创建 MaskablePPO 模型。MaskablePPO 是支持动作掩蔽的 PPO 变体，它能根据当前表达式结构屏蔽非法动作（如一元算子不能选二元算子的操作数）。

features_extractor_class=LSTMSharedNet 是 AlphaSAGE 自定义的 LSTM 特征提取器。它与 GFlowNet 的 RGCN 形成鲜明对比：LSTM 是序列模型，RGCN 是图模型。AlphaSAGE 试图通过这个对比证明“结构感知”的价值。

gamma=1. 是抵扣因子，表示不折未来奖励。这是 alpha 生成任务的特点：每个动作都直接影响最终表达式，不需要折未来。ent_coef=0.01 是熵系数，与 GFlowNet 的熵正则项引入同一思想，但 PPO 是在上下文中软性加入，而非 GFlowNet 的 TB 损失中直接减去。

QCM 基线：分位式 RL

看 QCM 入口。共享部分同样是数据与 target。第 47-53 行创建 AlphaPool 与 AlphaEnv，与 PPO 一致。

与 GFlowNet 的区别在于：QCM 是值基 RL，学习 Q(s, a)；GFlowNet 是生成模型，学习 P_F(τ)。值基 RL 倾向于找到单一最优动作，而 GFlowNet 采样多样轨迹。这个对比是 AlphaSAGE 论文的核心论点之一。

QCM 皂型训练与 GFlowNet 同样需要大量迭代与调超参数，但它们不需要后向策略（P_B），实现上更简单。但代价是它们并不保证多样性。

AFF 基线：融合组合

AFF 是另一类基线，用 GAN 生成 alpha 并用加权融合。它与 GFlowNet 的区别在于“怎么生成”与“怎么组合”。

这里是 AFF 的滚动组合逻辑，与 GFlowNet 的 run_adaptive_combination.py 高度对称。第 182-185 行定义滚动窗口。第 187-200 行计算窗口内 IC 与 ICIR。第 213-222 行筛选优质 alpha，使用 RankIC 与 RankICIR 阈值，与 GFlowNet 的逻辑完全一致。

第 226-243 行准备回归数据，添加常数项。第 246 行调用 torch.linalg.lstsq 求解 OLS，与 GFlowNet 完全一致。这里可以看出，AFF 与 GFlowNet 在“组合阶段”完全同框架，区别只在“生成阶段”（GAN vs GFlowNet）。

这个设计让对比变得公平：如果 GFlowNet 生成的 alpha 池在同一个组合器（OLS 回归）下表现更优，那么可以确定是“生成”环节的优势，而非“组合”环节的优势。

数据流

三类基线的共享数据流：StockData → target → AlphaPool → AlphaEnv → 策略 → 训练 → pool_*.json → 组合 → 指标。

具体来说，三类基线都使用同一个 instrument（如 csi300）与同一个 target（未来 20 天收益），训练后输出各自的 pool_*.json。组合阶段都用 torch.linalg.lstsq 求解 OLS，输出 ret_s.npy。最后用 get_tensor_metrics 计算 IC、ICIR、夏普、MDD，进行同框架对比。

设计权衡

为什么选择 PPO 作为传统 RL 基线？PPO 是强化学习中最被广泛使用的算法之一，它性能稳定、调超参数少。与之对比可以说明 GFlowNet 相对于传统 RL 的优势。

为什么选择 QCM 作为分位式 RL 基线？QCM 代表了“估计 Q 值分布”这一类方法，与 PPO 代表的“估计期望值”互为补充。与 GFlowNet 对比可以说明“生成模型”相对于“值基 RL”的优势。

为什么选择 AFF 作为生成器基线？AFF 代表了“用 GAN 生成 alpha”这一类方法。与 GFlowNet 对比可以说明“路径采样”相对于“GAN 生成”的优势。且 AFF 复用了 GFlowNet 的组合逻辑，让对比变得公平。

为什么三类基线共享 AlphaPool 与 AlphaEnv？因为这样可以排除环境与池的差异，只让“策略与生成器”成为变量。如果各自实现不同的池与环境，就难以说明“结果差异是由策略造成的”。

小结

本章讲解了 AlphaSAGE 的三类基线：PPO、QCM、AFF。它们共享 StockData、AlphaPool、AlphaEnv 接口，各自用不同策略生成 alpha，最后都用同一个组合器与指标评估。

这套设计让 AlphaSAGE 的“GFlowNet + RGCN + 多维奖励”与其他方法公平同台竞技。读者可以根据这些对比评估自己的判断。
