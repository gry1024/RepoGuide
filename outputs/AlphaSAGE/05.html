第5章：Alpha 池管理

像选秀节目的待定席，新选手要与现有成员比相关性，达标才入围、末位被淘汰。

欢迎

GFlowNet 每轮都会采样出大量表达式，但绝大多数是平庸甚至无效的。如果全部留下，池会迅速被噪声填满；如果只留 IC 最高的，又会丧失多样性。AlphaPoolGFN 是这道权衡题的答案：它维护一个固定容量的候选池，按 IC 与互相关双门槛 决定去留，并额外存储每个因子的结构嵌入，为第 6 章的 SSL 奖励铺路。

本章深入 src/alpha_gfn/alpha_pool.py 的两个核心方法：try_new_expr（入池判定）和 _find_k_nearest_neighbors（嵌入 KNN）。你会看到「选秀节目」式的淘汰机制：新选手要与现有成员比相关性，达标才入围，末位被淘汰。

它解决什么问题？

alpha 生成的核心矛盾是质量与多样性的平衡。质量看 IC——预测力强的因子才值得留；多样性看互相关——高度相关的因子重复了等于浪费池容量。如果只按 IC 排序，池里会塞满本质相同的因子（比如 TsMean($close,20)` 和 `TsMean($close,21)），组合时无法分散风险。

AlphaPoolGFN 的解法是双门槛：新因子要 IC 达标且与池内所有因子的互相关 ≤ ic_mut_threshold（默认 0.3）才入池。池满后，新因子要同时强过最弱因子并满足相关性约束，才触发末位淘汰。这保证了池里每个因子都既「有用」又「不可替代」。

核心设计思路

设计上有三个要点。第一，容量守恒：池满后采用「先加后弹」策略，先把新因子加入（size 变 capacity+1），再弹出 IC 最低的，保证容量始终守恒。第二，嵌入并行存储：每个因子除了值与 IC，还存一份结构嵌入，KNN 查询用。第三，新颖度作为奖励信号：入池判定返回的 (ic_ret, novelty) 里，novelty = 1 - max(互相关)，直接喂给第 6 章的奖励函数。

代码深入

try_new_expr —— 入池判定核心

这是池管理的心脏。它求值表达式、算 IC 与互相关，然后按池是否满走两条分支。注意末位淘汰的「先加后弹」顺序。

alpha_pool.py第 28-57 行
28    def try_new_expr(self, expr: Expression, embedding: Optional[Tensor] = None) -> Tuple[float, float]:  # 入池判定：评估表达式并按 IC/互相关决定去留
29        value = self._normalize_by_day(expr.evaluate(self.data))  # 表达式求值后按日归一化，得因子值张量
30        ic_ret, ic_mut = self._calc_ics(value, ic_mut_threshold=0.99)  # 同时算对目标的 IC 与对池内现有因子的互相关
31        if ic_ret is None or ic_mut is None:  # 求值失败（越界等）直接返回 0 奖励
32            return 0.0, 1.0
33        ic_ret = np.abs(ic_ret)  # 取绝对值，IC 方向不影响入池
34        ic_mut = np.abs(ic_mut)
35        
36        # Check if we should add this factor to the pool
37        if self.size < self.capacity:  # 池未满：只要互相关不超阈值就直接加入
38            # Pool not full, add directly if correlation constraint is satisfied
39            if ic_mut.size == 0 or np.max(ic_mut) <= self.ic_mut_threshold:  # 互相关最大值 ≤ 阈值，保证多样性
40                self._add_factor(expr, value, ic_ret, ic_mut, embedding)
41                print(f"[Pool Add] {expr}")  # 入池成功打印表达式
42        else:
43            # Pool is full, check if this factor is better than the worst one
44            min_ic_idx = np.argmin(self.single_ics[:self.size])  # 池已满：找最弱者比较，更强才替换
45            min_ic = self.single_ics[min_ic_idx]
46            
47            if ic_ret > min_ic and (ic_mut.size == 0 or np.max(ic_mut) <= self.ic_mut_threshold):  # 新因子 IC 高于最弱 且 互相关达标，才淘汰
48                # Add the new factor first (this will make size = capacity + 1)
49                self._add_factor(expr, value, ic_ret, ic_mut, embedding)  # 先加新因子（size 变 capacity+1）
50                print(f"[Pool Add] {expr}")
51                # Then remove the worst factor using _pop  # 再弹出 IC 最低的，容量守恒
52                print(f"[Pool Pop] {self.exprs[np.argmin(self.single_ics[:self.size])]}")
53                self._pop()  # 末位淘汰：_pop 内部找 argmin single_ics
54            else:
55                print(f"[Pool Reject] {expr}")
56        
57        return ic_ret, (1 - np.max(ic_mut)) if ic_mut.size > 0 else 1.0  # 返回 IC 与新颖度（1 - 最大互相关）

第 30 行 _calc_ics 一次算出两类相关：对目标的 IC（预测力）和对池内现有因子的互相关（重复度）。这两者共同决定入池资格。第 33-34 行取绝对值——负 IC 的因子只要稳定也能用（反向操作即可），所以入池只看绝对值。

第 47-53 行的「先加后弹」是精妙的设计。为什么不直接比较后替换？因为 _pop 用 argmin(single_ics) 找最弱，如果先弹后加，中间状态 size 会瞬时变小，可能让其他逻辑出错。先加到 capacity+1 再弹回 capacity，容量始终在 [size, capacity+1] 之间，状态机更简单。第 52 行还打印被弹出因子，方便调试观察池的演化。

第 57 行返回的 novelty = 1 - max(ic_mut) 是关键。它把「与池内最相似因子的相关性」转成 (0,1] 的新颖度分数——完全独立的新因子 novelty=1，与某因子完全相关的 novelty=0。这个分数会作为奖励的一部分（第 6 章），驱动 GFlowNet 去探索池里还没覆盖的方向。

_find_k_nearest_neighbors —— 基于嵌入的 KNN

SSL 奖励的前置：在嵌入空间找 k 个最近邻。用 L2 距离，并排除自身（距离极小的视为同一表达式）。

alpha_pool.py第 90-138 行
90    def _find_k_nearest_neighbors(self, query_embedding: Tensor, k: int, exclude_self: bool = True, distance_threshold: float = 1e-6) -> List[int]:  # 基于嵌入 L2 距离的 KNN，SSL 奖励的前置
91        """
92        Find k nearest neighbors based on embedding similarity
93        
94        Args:
95            query_embedding: The embedding to find neighbors for
96            k: Number of neighbors to find
97            exclude_self: Whether to exclude identical embeddings (distance ≈ 0)
98            distance_threshold: Minimum distance to consider as different embeddings
99            
100        Returns:
101            List of indices of k nearest neighbors
102        """
103        if self.size <= 1:  # 池内不足 2 个因子时无近邻可查
104            # print(f"[SSL Debug] Pool size <= 1 ({self.size}), no neighbors available")
105            return []
106        
107        distances = []  # 收集候选距离与索引
108        valid_indices = []
109        
110        for i in range(self.size):  # 遍历池中每个因子的嵌入
111            if self.embeddings[i] is not None:  # 跳过无嵌入的槽位
112                # Calculate L2 distance
113                dist = torch.norm(query_embedding - self.embeddings[i]).item()  # 计算查询嵌入与候选嵌入的 L2 距离
114                
115                # Skip if this is likely the same embedding (distance ≈ 0)
116                if exclude_self and dist < distance_threshold:  # 排除自身：距离极小视为同一表达式
117                    # print(f"[SSL Debug] Factor {i}: distance = {dist:.6f} (SKIPPED - too similar/identical)")
118                    continue
119                    
120                distances.append(dist)
121                valid_indices.append(i)
122                # print(f"[SSL Debug] Factor {i}: distance = {dist:.6f}")
123        
124        if len(distances) == 0:  # 无合法候选则返回空
125            # print(f"[SSL Debug] No valid embeddings found in pool (after excluding self)")
126            return []
127        
128        # Get k smallest distances (nearest neighbors)
129        k = min(k, len(distances))  # k 不超过合法候选数
130        _, indices = torch.topk(torch.tensor(distances), k, largest=False)  # topk 取最小 k 个距离对应索引
131        
132        neighbor_indices = [valid_indices[idx] for idx in indices.tolist()]  # 映射回池内真实索引
133        neighbor_distances = [distances[idx] for idx in indices.tolist()]
134        
135        # print(f"[SSL Debug] Found {len(neighbor_indices)} neighbors: {neighbor_indices}")
136        # print(f"[SSL Debug] Neighbor distances: {[f'{d:.6f}' for d in neighbor_distances]}")
137        
138        return neighbor_indices

第 113 行用 torch.norm 算 L2 距离。为什么用 L2 而非余弦相似度？因为 RGCN 池化后的嵌入范数本身携带信息（更复杂的表达式嵌入范数可能不同），L2 同时考虑方向与幅度。第 116 行的 distance_threshold=1e-6 排除自身——同一个表达式再查一次距离必然极小，会被误当近邻，必须剔除，否则 SSL 奖励会退化成自相关。

第 130 行 torch.topk(distances, k, largest=False) 取最小的 k 个。注意它对距离张量操作，再用 valid_indices 映射回池内真实位置——因为遍历时跳过了无嵌入的槽位，索引不连续。这种「候选列表 + 索引映射」是处理稀疏存储的标准模式。

设计权衡为什么互相关阈值设 0.3？太严（如 0.1）会让池很难填满，多样性过剩但质量不足；太松（如 0.6）会让因子高度重复，组合时无法分散风险。0.3 是经验上「足够独立又不过分苛刻」的折中。另外，池容量默认 10——小池让组合更稳健（避免过拟合），大池让单因子更易被淘汰（探索更强）。
小结AlphaPoolGFN 用 IC + 互相关双门槛做入池判定，先加后弹保证容量守恒。返回的新颖度直接作为奖励信号。_find_k_nearest_neighbors 在嵌入空间找近邻，为 SSL 奖励铺路。池既是生成器的「记忆」，也是组合的「原料库」。

关联公式

新颖度奖励的定义：

$$r_{\text{NOV}} = 1 - \max_{k} |IC_{\text{mut},k}|$$

对应第 57 行 (1 - np.max(ic_mut))。它把「与最相似因子的互相关」映射成 (0,1] 的奖励。KNN 的相似度权重则用温度 softmax：

$$w_i = \frac{\exp(-\|e_q - e_i\|^2 / \tau)}{\sum_j \exp(-\|e_q - e_j\|^2 / \tau)}$$

对应 _compute_similarity_weights（第 140-176 行），距离越小权重越大，$\tau$ 控制锐度。

小结

本章你看到了 alpha 池的双门槛筛选与末位淘汰。try_new_expr 决定去留，_find_k_nearest_neighbors 在嵌入空间找近邻。池管理的本质是在质量与多样性间找平衡——IC 保质量，互相关保多样性，结构嵌入为 SSL 奖励埋下伏笔。下一章我们就看这个奖励如何被合成成驱动 GFlowNet 的多维信号。
