第6章：多维奖励函数

像三味调料的递减配方，IC 主味之外加 SSL 与新颖度佐料，随训练推进逐渐收浓。

这个模块做什么

GFNEnvCore.reward（src/alpha_gfn/env/core.py）与 compute_ssl_reward（alpha_pool.py）合成 GFlowNet 的奖励信号。它们的输入是一条完整轨迹与池状态，输出是一个标量奖励，中间做三件事：算 IC 奖励、算 SSL 结构一致性奖励、算 NOV 新颖度奖励，再加权融合。三维信号分别管预测力、结构多样性、数值独立性。

SSL/NOV 权重随训练时间退火（由第 7 章的 WeightScheduler 控制），让生成器先探索后聚焦，避免单一 IC 奖励导致的模式崩塌。

它解决什么问题？

单一 IC 奖励的失败模式很典型：生成器发现 TsMean($close, 20) IC 不错，就开始围绕它做微调（改窗口、加 Abs），池里塞满本质相同的因子。组合时它们高度相关，无法分散风险，Mega-Alpha 退化成单因子。

三维奖励分别针对三个目标：IC 保证预测力；SSL（Self-Supervised Learning）用结构嵌入的 KNN 一致性，奖励「结构相近但数值不同」的因子，鼓励结构多样性；NOV 直接惩罚与池内因子的高相关，保证数值独立性。三者加权融合，权重由第 7 章的 WeightScheduler 随时间退火——训练初期 SSL/NOV 权重高，鼓励探索；后期降到接近 0，聚焦 IC。

核心设计思路

设计上有三个要点。第一，SSL 用结构嵌入而非数值：它比较的是 RGCN 提取的图嵌入，而非因子值本身——这样「结构相近」的因子会被奖励一致，即使数值不同。第二，一致性损失转奖励：ssl_reward = exp(-consistency_loss)，把损失映射成 (0,1] 的奖励，越一致奖励越高。第三，奖励下限保护：max(reward, exp(-10)) 保证奖励恒正，避免 GFlowNet 因零奖励而停止采样。

代码深入

GFNEnvCore.reward —— 三维奖励合成

这是 GFlowNet 的信号源。它逐条轨迹重建表达式，用池的 try_new_expr_with_ssl 一次拿到 IC/NOV/SSL 三路奖励，再按权重加权。注意嵌入是在 no_grad 下算的——只用于 SSL，不回传梯度。

140    def reward(self, final_states: DiscreteStates) -> torch.Tensor:  # 多维奖励合成：IC + λ·SSL + λ·NOV，GFlowNet 信号源
141        rewards = []
142        for state_tensor in final_states.tensor:  # 逐条轨迹重建表达式 token
143            builder = ExpressionBuilder()
144            token_ids = [tid.item() for tid in state_tensor if tid >= 0]  # 取 token id（过滤 -1 填充）
145            
146            # Reconstruct the expression for reward calculation
147            for token_id in token_ids[1:]:  # 跳过起始符 BEG_TOKEN，从第 2 个 token 建树
148                builder.add_token(self.id_to_token_map[token_id])
149
150            reward = 0.0  # 默认奖励 0；合法表达式才计算
151            if builder.is_valid():  # is_valid 校验语法完整（栈空、类型匹配）
152                try:
153                    expr = builder.get_tree()  # 把 token 序列转成 AST 表达式对象
154                    
155                    # Compute embedding only for this valid expression
156                    embedding = None
157                    if self.encoder is not None:  # 若有编码器，前向算结构嵌入
158                        with torch.no_grad():  # no_grad：嵌入只用于 SSL，不回传梯度

160                            single_state = state_tensor.unsqueeze(0)  # 单条状态加 batch 维，编码后 squeeze 回原维

163                    reward = ic_reward + self.ssl_weight * ssl_reward + self.nov_weight * nov_reward  # 按权重加权融合成最终标量奖励
164                except OutOfDataRangeError:  # 数据越界（窗口不足）时奖励归零
165                    reward = 0.0
166            rewards.append(np.maximum(reward, np.exp(-10)))  # 下限 exp(-10)≈4.5e-5，保证奖励恒正以驱动采样
167        
168        return torch.tensor(rewards, dtype=torch.float, device=self.device)

第 147 行 token_ids[1:] 跳过 BEG_TOKEN——状态张量第一个位置是起始符，不是表达式内容。第 151 行 builder.is_valid() 校验表达式语法完整：栈必须弹空、类型必须匹配（比如二元算子必须有两个操作数）。不合法的表达式奖励为 0，但第 166 行的下限让它变成 exp(-10)，而不是严格的 0——这是 GFlowNet 的要求：奖励必须恒正，否则前向概率会塌缩到不采样任何东西。

第 158 行的 torch.no_grad() 很关键。结构嵌入由 RGCN 编码器算出，而编码器同时是策略网络的一部分（共享 backbone）。如果让梯度流过这里，奖励会通过编码器反传，与策略损失耦合，训练会崩溃。no_grad 把嵌入当作固定指纹用，仅用于 SSL 一致性比较，梯度只在策略前向时流过编码器——这是 AlphaSAGE 训练能稳定的关键工程细节。

第 162 行 try_new_expr_with_ssl 一次返回三元组 (ic_reward, nov_reward, ssl_reward)。第 163 行按环境当前权重（由第 7 章的训练循环每步更新）加权融合。这种「奖励分量 + 动态权重」的设计，让同一套奖励机制能适应训练的不同阶段。

compute_ssl_reward —— 结构一致性自监督

SSL 奖励的计算链：找 k 近邻 → 算相似度权重 → 算一致性损失 → exp 映射成奖励。它衡量「查询因子的数值与结构近邻的数值有多一致」。

220    def compute_ssl_reward(self, expr: Expression, embedding: Optional[Tensor] = None) -> float:  # SSL 奖励：基于结构嵌入 KNN 一致性的自监督信号
221        """
222        Compute SSL (Self-Supervised Learning) reward based on structural consistency
223        
224        Args:
225            expr: The expression to compute SSL reward for
226            embedding: The structural embedding of the expression
227            
228        Returns:
229            SSL reward (positive value, higher is better)
230        """

232        # print(f"[SSL Debug] Pool size: {self.size}, K: {self.ssl_k}, τ: {self.ssl_tau}")

234        if embedding is None:  # 无嵌入则 SSL=0，退化为纯 IC 训练

246        neighbor_indices = self._find_k_nearest_neighbors(embedding, self.ssl_k, exclude_self=True)  # 在池中找 k 个嵌入最近邻（排除自身）

251        
252        # Compute similarity weights
253        weights = self._compute_similarity_weights(embedding, neighbor_indices)  # 用温度 softmax 算每个近邻的相似度权重
254        
255        if len(weights) == 0:

257            return 0.0
258

260        query_value = self._normalize_by_day(expr.evaluate(self.data))  # 查询表达式的因子值，按日归一化
261        
262        # Compute consistency loss
263        consistency_loss = self._compute_consistency_loss(query_value, neighbor_indices, weights)  # 计算查询与近邻因子值的加权 MSE 一致性损失
264        
265        # Transform consistency loss to SSL reward
266        ssl_reward = np.exp(-consistency_loss)  # exp(-loss) 把损失转成 (0,1] 奖励：越一致奖励越高
267        # print(f"[SSL Debug] Final SSL reward: {ssl_reward:.6f}")
268        # print(f"[SSL Debug] ===== SSL Reward Computation Done =====\n")
269        
270        return ssl_reward

SSL 的直觉是：如果两个表达式结构相近（嵌入距离小），它们应该数值也相近（因子值 MSE 小）。如果结构相近但数值差异大，说明生成器在「无意义地扰动结构」，应该被惩罚。第 263 行的 _compute_consistency_loss 算加权 MSE——近邻越相似（权重越大），它的一致性贡献越大。

第 266 行 ssl_reward = np.exp(-consistency_loss) 是经典的「损失转奖励」变换。损失为 0 时奖励 1（完全一致），损失越大奖励越接近 0。这种映射保证奖励在 (0,1] 区间，且对异常大损失不敏感（指数衰减）。结合第 5 章的 KNN，SSL 形成了完整的自监督回路：结构嵌入定义「相近」，数值一致性定义「好坏」，GFlowNet 据此调整采样方向。

设计权衡为什么 SSL 用结构嵌入而非数值近邻？因为数值近邻会让生成器去复制高 IC 因子的数值——又回到模式崩塌。结构嵌入近邻则鼓励「在相似结构上探索不同数值」，这是更健康的多样性。而 NOV（数值互相关）保证不出现数值重复。SSL 管结构多样性，NOV 管数值独立性，分工明确。
小结奖励 = IC + λ_ssl·SSL + λ_nov·NOV，三维信号由 reward 合成。SSL 用结构嵌入 KNN 做自监督一致性，exp(-loss) 转奖励。权重随训练退火（第 7 章）。no_grad 防止奖励梯度污染编码器。这是 AlphaSAGE 避免模式崩塌的核心机制。

关联公式

多维奖励的完整定义：

$$r = r_{\text{IC}} + \lambda_{\text{ssl}}(t)\, r_{\text{SSL}} + \lambda_{\text{nov}}(t)\, r_{\text{NOV}}$$

对应第 163 行。$\lambda$ 是时变权重，由 WeightScheduler 退火。SSL 奖励：

$$r_{\text{SSL}} = \exp(-L_{\text{consist}}), \quad w_i = \text{softmax}(-\|e_q - e_i\|^2 / \tau)$$

对应第 266 行与 _compute_similarity_weights。$L_{\text{consist}} = \sum_i w_i \cdot \text{MSE}(v_q, v_i)$。数学与代码逐项对应。

小结

三维奖励 IC+SSL+NOV 分别管预测力、结构多样性、数值独立性，权重随时间退火让生成器先探索后聚焦。SSL 巧妙复用第 4 章的结构嵌入做自监督。下一章我们看这套奖励如何被训练主循环消费——采样、算损失、退火权重、回传梯度，串成完整的训练流程。
