第 6 章：多维奖励函数

GFNEnvCore.reward 与 compute_ssl_reward —— IC + SSL + 新颖度三路信号合成

欢迎

欢迎来到第 6 章！前面几章我们讲了 GFlowNet、RGCN 编码、Alpha 池。这些组件都是为了“生成优质 alpha”这个目标服务。但“优质”是一个复杂概念，仅用 IC 作为奖励会导致模型贪婪地生成高 IC 但高度同质的 alpha。AlphaSAGE 用三个信号合成一个多维奖励，同时鼓励高 IC、结构一致性与新颖度。

本章会进入 env/core.py 的 reward 方法以及 alpha_pool.py 的 compute_ssl_reward，看它们如何合成总奖励，以及 SSL 奖励背后的“结构一致性”思想。

它解决什么问题？

类比来说，多维奖励像三味调料的递减配方，IC 主味之外加 SSL 与新颖度佐料，随训练推进逐渐收济。

仅用 IC 作为奖励有两个问题。其一，模型会贪婪地生成高 IC 但彼此高度相关的 alpha，丢失多样性；其二，IC 是稀疏信号，训练初期奖励平坦，难以提供梯度。AlphaSAGE 的解决方案是加入 SSL（结构一致性）与新颖度两个辅助信号：SSL 鼓励“结构相似的 alpha 要有相似的因子值”，起到软约束作用；新颖度鼓励“与现有 alpha 不同”，避免同质。两者权重随训练逐渐衰减，使模型最终主要被 IC 驱动。

核心设计思路

多维奖励的设计思路是三路信号加权合成 + 时间退火。

三路信号：r_IC（主信号，衡量预测能力）、r_SSL（结构一致性，基于 KNN 一致性）、r_NOV（新颖度，与现有池的互相关互补）。三者加权合成，权重由 WeightScheduler 动态调整。

时间退火：训练初期，SSL 与新颖度权重较高，帮助模型快速收敛并避免同质；后期这些辅助信号衰减到几乎为 0，让 IC 成为主导。这个“先帮扶后放手”的设计在训练智能体中很常见。

代码深入

reward：三路合成的核心

这个方法是环境给 GFlowNet 的最终奖励。它重建表达式、计算嵌入、调用池的 SSL 三路合成。

    def reward(self, final_states: DiscreteStates) -> torch.Tensor:
        rewards = []
        for state_tensor in final_states.tensor:
            builder = ExpressionBuilder()
            token_ids = [tid.item() for tid in state_tensor if tid >= 0]
            
            # Reconstruct the expression for reward calculation
            for token_id in token_ids[1:]:
                builder.add_token(self.id_to_token_map[token_id])

            reward = 0.0
            if builder.is_valid():
                try:
                    expr = builder.get_tree()
                    
                    # Compute embedding only for this valid expression
                    embedding = None
                    if self.encoder is not None:
                        with torch.no_grad():
                            # Add batch dimension for single state
                            single_state = state_tensor.unsqueeze(0)
                            embedding = self.encoder(single_state).squeeze(0)
                    ic_reward, nov_reward, ssl_reward = self.pool.try_new_expr_with_ssl(expr, embedding)
                    reward = ic_reward + self.ssl_weight * ssl_reward + self.nov_weight * nov_reward
                except OutOfDataRangeError:
                    reward = 0.0
            rewards.append(np.maximum(reward, np.exp(-10)))
        
        return torch.tensor(rewards, dtype=torch.float, device=self.device)

逻辑很清晰。第 142-148 行重建表达式：从状态张量取出 token_ids，调用 ExpressionBuilder 重建表达式树。第 151 行检查表达式是否合法（如括号配对、操作数足够）。

第 156-161 行计算嵌入：使用编码器对当前状态做前向，得到 RGCN 输出的嵌入。这里的 torch.no_grad() 很重要，避免奖励计算过程中反向传播到编码器（编码器的梯度应该只来自 GFlowNet 的 TB 损失）。

第 162-163 行是核心：调用 pool.try_new_expr_with_ssl(expr, embedding) 获取 IC、新颖度、SSL 三个奖励，然后加权合成：$$r = r_{IC} + \lambda_{ssl}(t)\,r_{SSL} + \lambda_{nov}(t)\,r_{NOV}$$。这个合成是 AlphaSAGE 多维奖励的核心创新。

第 166 行 np.maximum(reward, np.exp(-10)) 是一个防御性处理：奖励不能为 0（否则 log R 为 -inf，TB 损失会 NaN），所以设了一个很小的下限 exp(-10) ≈ 4.5e-5。

compute_ssl_reward：结构一致性奖励

这个方法是 SSL 奖励的计算逻辑。它查询 alpha 的近邻，权衡因子值与近邻的一致性，返回奖励。

    def compute_ssl_reward(self, expr: Expression, embedding: Optional[Tensor] = None) -> float:
        """
        Compute SSL (Self-Supervised Learning) reward based on structural consistency
        
        Args:
            expr: The expression to compute SSL reward for
            embedding: The structural embedding of the expression
            
        Returns:
            SSL reward (positive value, higher is better)
        """
        # print(f"\n[SSL Debug] ===== Computing SSL Reward =====")
        # print(f"[SSL Debug] Pool size: {self.size}, K: {self.ssl_k}, τ: {self.ssl_tau}")
        
        if embedding is None:
            # print(f"[SSL Debug] No embedding provided, SSL reward = 0.0")
            return 0.0
            
        if self.size <= 1:
            # print(f"[SSL Debug] Pool size <= 1, SSL reward = 0.0")
            return 0.0
        
        # print(f"[SSL Debug] Query embedding shape: {embedding.shape}")
        # print(f"[SSL Debug] Query embedding norm: {torch.norm(embedding).item():.4f}")
        
        # Find k nearest neighbors based on embedding similarity (excluding self)
        neighbor_indices = self._find_k_nearest_neighbors(embedding, self.ssl_k, exclude_self=True)
        
        if not neighbor_indices:
            # print(f"[SSL Debug] No neighbors found, SSL reward = 0.0")
            return 0.0
        
        # Compute similarity weights
        weights = self._compute_similarity_weights(embedding, neighbor_indices)
        
        if len(weights) == 0:
            # print(f"[SSL Debug] No weights computed, SSL reward = 0.0")
            return 0.0
        
        # Get normalized factor values
        query_value = self._normalize_by_day(expr.evaluate(self.data))
        
        # Compute consistency loss
        consistency_loss = self._compute_consistency_loss(query_value, neighbor_indices, weights)
        
        # Transform consistency loss to SSL reward
        ssl_reward = np.exp(-consistency_loss)
        # print(f"[SSL Debug] Final SSL reward: {ssl_reward:.6f}")
        # print(f"[SSL Debug] ===== SSL Reward Computation Done =====\n")
        
        return ssl_reward

逻辑很清晰。第 246 行调用 _find_k_nearest_neighbors 查近邻（第 5 章讲过）。第 253 行调用 _compute_similarity_weights 计算权重。第 260 行求值得查询 alpha 的因子值。第 263 行调用 _compute_consistency_loss 计算与近邻因子值的 MSE 损失。

第 266 行是 SSL 奖励的关键转换：$$r_{SSL} = \exp(-L_{consist})$$。这个转换很巧妙：一致性损失越小（因子值与近邻越接近），奖励越接近 1；损失越大，奖励越小（但仍为正）。这让 SSL 奖励始终保持在 (0, 1] 区间，与 IC 奖励同尺度。

这里的思想是“结构相似的 alpha 应该有相似的因子值”。这是一个强假设：如果两个表达式的语法结构接近（如 TsMean($close, 10) 与 TsMean($close, 20)），它们提供的信息也应该接近。这起到了正则化作用，避免模型产出结构上一致但数值异常的 alpha。

一致性损失计算

    def _compute_consistency_loss(self, query_value: Tensor, neighbor_indices: List[int], weights: Tensor) -> float:
        """
        Compute consistency loss between query factor and its neighbors
        
        Args:
            query_value: Normalized factor values for the query factor
            neighbor_indices: Indices of neighbor factors
            weights: Similarity weights
            
        Returns:
            Consistency loss value
        """
        if not neighbor_indices or len(weights) == 0:
            # print(f"[SSL Debug] No neighbors or weights for consistency loss")
            return 0.0
        
        total_loss = 0.0
        individual_losses = []
        
        # print(f"[SSL Debug] Computing consistency loss with {len(neighbor_indices)} neighbors")
        # print(f"[SSL Debug] Query value shape: {query_value.shape}")
        
        for i, idx in enumerate(neighbor_indices):
            if idx < len(self.values) and self.values[idx] is not None:
                neighbor_value = self.values[idx]
                
                # Calculate MSE loss per cross-section and average
                diff_squared = (query_value - neighbor_value) ** 2
                mse_per_section = diff_squared.mean(dim=1)  # Average across stocks in each day
                avg_mse = mse_per_section.mean().item()  # Average across days
                
                weighted_loss = weights[i].item() * avg_mse
                total_loss += weighted_loss
                individual_losses.append(avg_mse)
                
                # print(f"[SSL Debug] Neighbor {idx}: MSE={avg_mse:.6f}, weight={weights[i].item():.4f}, weighted_loss={weighted_loss:.6f}")
        
        # print(f"[SSL Debug] Individual MSE losses: {[f'{loss:.6f}' for loss in individual_losses]}")
        # print(f"[SSL Debug] Total consistency loss: {total_loss:.6f}")
        
        return total_loss

这里是一致性损失的详细计算。对每个近邻，计算查询因子与该近邻因子的 MSE，按权重加权求和。

第 205-207 行的 diff_squared = (query_value - neighbor_value) ** 2 与 mse_per_section = diff_squared.mean(dim=1) 是 MSE 的计算。dim=1 是股票维，对股票取平均得到每天的 MSE，再对天取平均得到总 MSE。

权重的计算在 _compute_similarity_weights 中：$$w_i = \text{softmax}(-\|e_q - e_i\|^2/\tau)$$。这个 softmax 让越近的近邻获得越大的权重，使一致性损失主要由近邻决定。

数据流

数据流：环境重建表达式 → 编码器计算嵌入 → 池的 try_new_expr_with_ssl 返回 IC/NOV/SSL → reward 加权合成 → 传给 GFlowNet。

这个奖励会被 GFlowNet 的 TB 损失使用（第 3 章），通过 log R 进入损失。与此同时，环境中的 ssl_weight 与 nov_weight 会被 WeightScheduler 动态调整（第 7 章），实现时间退火。

关联公式

$$r = r_{IC} + \lambda_{ssl}(t)\,r_{SSL} + \lambda_{nov}(t)\,r_{NOV}$$
$$r_{SSL} = \exp(-L_{consist}),\quad w_i = \text{softmax}(-\|e_q-e_i\|^2/\tau)$$

第一个公式对应代码 reward = ic_reward + self.ssl_weight * ssl_reward + self.nov_weight * nov_reward。第二个公式描述了 SSL 奖励与权重的计算。

这两个公式是 AlphaSAGE 多维奖励的数学核心，也是与传统 RL 最大的不同之处。

设计权衡

为什么选择 exp 转换而不是直接用负损失？因为奖励应该为正（与 IC 同尺度），且软化了差异：即使一致性损失很大，奖励也不会变负；即使损失为 0，奖励也不会超过 1，避免 SSL 项主宰 IC 项。

为什么用 softmax 权重而不是均等权重？均等权重让所有近邻一视同仁，但近邻中越近的应该越有发言权。softmax 让距离越近的近邻获得越大权重，使一致性主要由最近的近邻决定。

为什么要时间退火？训练初期需要 SSL 与新颖度帮助模型快速收敛、避免同质；后期应该让 IC 成为主导，避免辅助信号干扰最终预测能力。退火让这个过渡自然发生。

小结

本章讲解了多维奖励函数：从 reward 的三路合成到 compute_ssl_reward 的结构一致性逻辑。这是 AlphaSAGE 的核心创新：用多维奖励同时鼓励高 IC、结构一致与新颖度。
