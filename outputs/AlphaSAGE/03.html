第 3 章：GFlowNet 生成框架

EntropyTBGFlowNet —— Trajectory Balance 损失与熵正则项的采样框架

欢迎

欢迎来到第 3 章！前两章我们讲了数据与表达式体系，现在终于进入 AlphaSAGE 的核心：GFlowNet。这是整个项目最重要的一章，因为它实现了“多样化生成”这个核心能力—— 与传统 RL 不同，GFlowNet 不是找一条最优路径，而是同时探索多条路径，采样出与奖励成正比的多样表达式。

本章会进入 gflownet.py，从 Trajectory Balance 的数学原理讲起，然后看代码如何计算 log_pf、log_pb、熵项，最后看 TB 损失函数如何把这些量组合成梯度。

它解决什么问题？

类比来说，GFlowNet 像一个多路探险家，同时派许多路径去采样不同 alpha，而非只走一条最优路。

传统强化学习（如 PPO）在 alpha 挑挘中有一个致命问题：它倾向于“贪婪”地找到一个高 IC 的 alpha 后反复生成它，导致 alpha 池中高度同质。但量化研究中我们需要多样化的 alpha 来做组合，互相补充。GFlowNet 解决这个问题：它学习的是一个采样分布 P_F，使得采样到某个 alpha 的概率正比于它的奖励 R。这样高奖励的 alpha 会被多采样，低奖励的也会被采样到但频率较低，保讹了多样性。

核心设计思路

GFlowNet 的核心思想是Trajectory Balance（TB）。它要求从起始状态 s_0 到终止状态 x 的任何路径 τ，都满足：

P_F(τ) · Z = R(x) · P_B(τ)，其中 P_F 是前向策略（从 s_0 走到 x），P_B 是后向策略（从 x 回到 s_0），Z 是使两边相等的配分函数，R(x) 是状态 x 的奖励。取对数后变成：log P_F(τ) + log Z = log R(x) + log P_B(τ)，移项后可以定义损失为两边的 MSE。

为了避免模型过早收敛、挖掘出单一最优解，AlphaSAGE 在 TB 损失上加了熵正则项：鼓励前向策略 P_F 在每一步保持较高熵，避免确信度过高。这就是 EntropyTBGFlowNet 的由来。

代码深入

类定义与构造

import torch
from typing import Tuple
from gfn.containers import Trajectories
from gfn.env import Env
from gfn.gflownet.trajectory_balance import TBGFlowNet
from gfn.modules import DiscretePolicyEstimator
from torchtyping import TensorType as TT


class EntropyTBGFlowNet(TBGFlowNet):
    def __init__(
        self,
        pf: DiscretePolicyEstimator,
        pb: DiscretePolicyEstimator,
        entropy_coef: float = 0.0,
        entropy_temperature: float = 1.0,
        **kwargs,
    ):
        super().__init__(pf, pb, **kwargs)
        self.entropy_coef = entropy_coef
        self.entropy_temperature = entropy_temperature

EntropyTBGFlowNet 继承自 TBGFlowNet（来自 gfn 库），额外加入了两个参数：entropy_coef（熵正则项系数）与 entropy_temperature（计算熵时的温度）。

传入的 pf 与 pb 是 DiscretePolicyEstimator，分别是前向和后向策略估计器。它们内部包含了编码器（下一章的 RGCN）和一个简单的线性输出头，输出每个 token 的 logit。

get_trajectories_scores：计算每条轨迹的分数

这个方法计算每条采样轨迹的 log_pf、log_pb、scores 和熵项。它是损失函数的数据来源。

    def get_trajectories_scores(
        self, trajectories: Trajectories, recalculate_all_logprobs: bool = False
    ) -> Tuple[
        TT["n_trajectories", torch.float],
        TT["n_trajectories", torch.float],
        TT["n_trajectories", torch.float],
        TT["n_trajectories", torch.float]
    ]:
        if self.entropy_coef <= 0:
            return (*super().get_trajectories_scores(trajectories, recalculate_all_logprobs), torch.zeros(trajectories.n_trajectories, device=trajectories.states.device))

        log_pf, log_pb, scores = super().get_trajectories_scores(
            trajectories, recalculate_all_logprobs
        )

        # Calculate entropy term
        entropy_term = torch.zeros(trajectories.n_trajectories, device=trajectories.states.device)
        if trajectories.estimator_outputs is not None:
            logits = trajectories.estimator_outputs  # (max_len, batch_size, n_actions)
            temp_logits = logits / self.entropy_temperature
            probs = torch.softmax(temp_logits, dim=-1)
            entropy_per_step = -torch.sum(
                probs * torch.log(probs.clamp(min=1e-9)), dim=-1
            )  # (max_len, batch_size)

            # Mask out invalid steps for each trajectory
            max_len = logits.shape[0]
            step_indices = torch.arange(max_len, device=logits.device).unsqueeze(1)
            valid_steps_mask = step_indices < trajectories.when_is_done.unsqueeze(0)

            masked_entropy = entropy_per_step * valid_steps_mask

            # Sum entropy over trajectory steps for each trajectory in the batch
            entropy_sum_per_trajectory = masked_entropy.sum(dim=0)  # (batch_size,)

            entropy_term = entropy_sum_per_trajectory * self.entropy_coef
        elif self.entropy_coef > 0:
            # Fallback for older gfn versions or if outputs are not saved

这个方法的逻辑很巧妙。它先调用父类的 super().get_trajectories_scores() 拿到 log_pf、log_pb、scores，这些是 gfn 库默认实现的。然后计算熵项，这里是重点。

第 41-46 行是熵的核心计算：从 trajectories.estimator_outputs 拿到每一步的 logits（形状 (max_len, batch_size, n_actions)），除以温度 entropy_temperature，softmax 得到概率，然后套用熵公式 H = -sum(p * log p)。

第 49-53 行是 mask 逻辑：只对有效步骤计算熵。一条轨迹可能在第 5 步就结束，那么第 6 步以后的 logits 是无效的，需要被 mask 掉。when_is_done 记录了每条轨迹在哪一止，valid_steps_mask 则是一个布尔矩阵，表示哪些步骤是有效的。

最后乘以 entropy_coef 得到熵项，这个项会在损失中被减去，起到鼓励高熵的作用。

loss：TB 损失的核心

    def loss(
        self,
        env: Env,
        trajectories: Trajectories,
        recalculate_all_logprobs: bool = False,
    ) -> TT[0, float]:
        """Trajectory balance loss.

        The trajectory balance loss is described in 2.3 of
        [Trajectory balance: Improved credit assignment in GFlowNets](https://arxiv.org/abs/2201.13259))

        Raises:
            ValueError: if the loss is NaN.
        """
        del env  # unused
        _, _, scores, entropy_term = self.get_trajectories_scores(
            trajectories, recalculate_all_logprobs=recalculate_all_logprobs
        )
        loss = (scores + self.logZ).pow(2).mean() - entropy_term.mean()
        if torch.isnan(loss):
            # set inf
            loss = torch.tensor(float('inf'))

        return loss

这是整个 GFlowNet 的核心。第 96-98 行调用 get_trajectories_scores 拿到 scores 和 entropy_term，第 99 行就是 TB 损失公式的代码实现。

公式：$$L_{TB} = \mathbb{E}\left[\left(\log\frac{P_F(\tau)}{P_B(\tau)R(\tau)} + \log Z\right)^2\right] - \lambda_H H(\pi)$$

对应代码 loss = (scores + self.logZ).pow(2).mean() - entropy_term.mean()。这里 scores = log P_F - log P_B - log R（由父类计算），加上 logZ 后平方，就是 TB 的核心损失。减去熵项后，就实现了“TB + 熵正则”这个双重目标。

最后两行是 NaN 检查：如果损失出现 NaN（通常因为采样到了异常表达式导致奖励为 0），返回无穿大，让优化器跳过这个 batch，避免训练崩溃。

数据流

数据流：环境采样轨迹 → get_trajectories_scores 计算 log_pf/log_pb/熵 → loss 合成 TB 损失 → 优化器反向传播。

具体来说，训练循环（第 7 章）调用 sampler.sample_trajectories 采样 N 条轨迹，轨迹中包含了每一步的状态与动作。这些轨迹被传给 loss_fn.loss(env, trajectories)，内部调用 get_trajectories_scores，计算损失。这个损失会被 PyTorch 的自动微分机制传回到编码器参数，完成一次参数更新。

关联公式

$$L_{TB} = \mathbb{E}\left[\left(\log\frac{P_F(\tau)}{P_B(\tau)R(\tau)} + \log Z\right)^2\right] - \lambda_H H(\pi)$$
$$H(\pi) = -\sum_a \pi(a)\log\pi(a)$$

第一个公式对应 loss 函数的 (scores + self.logZ).pow(2).mean() - entropy_term.mean()。其中 scores 包含了 log P_F − log P_B − log R。

第二个公式是熵的定义，对应代码中的 -torch.sum(probs * torch.log(probs.clamp(min=1e-9)), dim=-1)。clamp(min=1e-9) 是为了避免 log(0) 产生 NaN。

设计权衡

为什么选择 Trajectory Balance 而不是 Flow Matching？TB 是 GFlowNet 中较早也较简单的变体，它在整条轨迹上定义损失，只需要起始与终止两端的平衡，计算量较小。Flow Matching 虽然更精细，但需要中间状态的完美估计，实现复杂。对于 alpha 表达式生成这种离散动作空间，TB 是合适的折中。

为什么要加熵正则？因为 TB 本身不能避免模型走向“确信度极高的单一解”。熵正则项起到“软化”作用，让模型在多个动作上保持非零概率，从而保讹多样性。这与 AlphaSAGE 设计初衷一致。

为什么 entropy_temperature 可调？温度越高，softmax 后的分布越平均（熵越高）；温度越低，分布越锐利（熵越低）。调整温度可以控制正则项的强度，适应不同阶段的训练需求。

小结

本章讲解了 GFlowNet 生成框架：从 TB 的数学原理到 EntropyTBGFlowNet 的代码实现。损失函数 (scores + logZ)^2 - entropy 同时驱动模型学习“采样与奖励成正比”以及“保持高熵”。
