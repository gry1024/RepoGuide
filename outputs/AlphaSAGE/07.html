第7章：训练主循环

像乐队指挥，按节拍采样轨迹、调度权重、回传梯度，把生成器一步步推向高产。

欢迎

前六章拼好了所有零件：数据接口、表达式词表、GFlowNet 损失、RGCN 编码器、Alpha 池、多维奖励。现在需要一个「指挥」把它们串起来——按节拍采样轨迹、调度权重、回传梯度，把生成器一步步推向高产。这就是 train_gfn.py 的 train 函数，AlphaSAGE 的训练主循环。

本章还涉及一个关键组件 WeightScheduler——它用 PyTorch 的学习率调度器实现 SSL/NOV 权重的时间退火，是论文里「先探索后聚焦」策略的工程落点。我们将逐段拆解训练循环与权重调度。

它解决什么问题？

GFlowNet 训练有几个工程难题。第一，梯度累积：每步只采样 1 条轨迹，梯度噪声大，需要累积 update_freq 步再更新一次，模拟小批量。第二，权重退火：SSL/NOV 权重不能恒定，初期要高（鼓励探索），后期要低（聚焦 IC），需要一个调度器。第三，数值稳定：logZ 容易跑飞，损失可能 NaN，需要保护。第四， checkpoint 与日志：训练动辄百万步，必须定期保存池与模型。

核心设计思路

设计上有四个要点。第一，复用 PyTorch 调度器做权重退火：WeightScheduler 把 SSL/NOV 权重当作「学习率」，用 LinearLR/ExponentialLR/PolynomialLR 衰减，巧妙避免手写退火逻辑。第二，环境权重热更新：每步从调度器取新权重，写回 env.ssl_weight/nov_weight，奖励函数立刻生效。第三，梯度累积与有限性检查：仅当损失有限才累计，每 update_freq 步反向传播。第四，TensorBoard + JSON 双日志：指标进 TensorBoard，池状态存 JSON，方便回测与可视化。

代码深入

WeightScheduler.get_current_weights —— 权重退火

这个方法复用 PyTorch 学习率调度器的衰减机制来管理奖励权重。初始权重乘以当前「学习率」（即衰减系数）得到当前权重。

train_gfn.py第 131-139 行
131    def get_current_weights(self):  # 读取当前 SSL/NOV 权重（时间退火核心）
132        """Get current weight values"""
133        ssl_lr = self.ssl_scheduler.get_last_lr()[0]  # 从 PyTorch 调度器拿当前学习率（复用为衰减系数）
134        nov_lr = self.nov_scheduler.get_last_lr()[0]  # NOV 同理
135        
136        current_ssl_weight = self.initial_ssl_weight * ssl_lr  # 当前 SSL 权重 = 初始值 × 衰减系数
137        current_nov_weight = self.initial_nov_weight * nov_lr  # 当前 NOV 权重 = 初始值 × 衰减系数
138        
139        return current_ssl_weight, current_nov_weight  # 返回当前权重供环境使用

这是个很聪明的复用。LinearLR(start_factor=1.0, end_factor=final_ratio) 会让「学习率」从 1.0 线性降到 final_ratio。把它乘到初始权重上，权重就从 initial_ssl_weight 线性降到 initial_ssl_weight * final_ratio。final_ratio 默认 0.0，意味着训练末期 SSL/NOV 完全关闭，奖励退化为纯 IC——这就是「先探索后聚焦」。

step() 每轮调用一次推进调度器。scheduler_type 支持 linear/exponential/polynomial，对应不同的退火曲线。线性最直观，指数衰减更快适合长训练，polynomial（power=2）则前期衰减慢、后期快，适合希望前期充分探索的场景。这种参数化让一套代码覆盖多种退火策略。

train 主循环 —— 采样、累积、更新

这是训练的心脏。每 episode：取权重→更新环境→采样→算损失→累积→定期更新。注意第 244 行的有限性检查与第 247 行的梯度累积。

train_gfn.py第 230-266 行
230    for episode in tqdm(range(n_episodes)):  # 主循环：逐 episode 采样、累积梯度、定期更新
231        # Get current weights from scheduler
232        current_ssl_weight, current_nov_weight = weight_scheduler.get_current_weights()  # 每步从调度器取当前退火权重
233        
234        # Update environment weights
235        env.ssl_weight = current_ssl_weight  # 把新 SSL 权重写回环境
236        env.nov_weight = current_nov_weight  # 把新 NOV 权重写回环境
237        
238        save_estimator_outputs = args.entropy_coef > 0  # 若启用熵正则，采样时保存 estimator_outputs
239        trajectories = sampler.sample_trajectories(  # 采样 1 条轨迹（n_trajectories=1）
240            env=env, n_trajectories=1, save_estimator_outputs=save_estimator_outputs
241        )
242        loss = loss_fn.loss(env=env, trajectories=trajectories)  # 计算 TB 损失（含熵正则）
243
244        if loss is not None and torch.isfinite(loss):  # 仅当损失有限才累计，避免 NaN 污染
245            minibatch_loss += loss
246            
247        if episode > 0 and (episode + 1) % update_freq == 0 and minibatch_loss != 0:  # 每 update_freq 步反向传播一次（小批量累积）
248            losses.append(minibatch_loss.item())
249            minibatch_loss.backward()  # 反向传播
250            optimizer.step()  # 优化器步进
251            optimizer.zero_grad()  # 清零梯度
252            minibatch_loss = 0  # 重置累积损失
253
254        if episode > 0 and (episode + 1) % args.log_freq == 0:  # 按 log_freq 记录指标
255            logger.log_metrics(episode)  # 记录池大小/IC 等到 TensorBoard
256            logger.save_checkpoint(episode)  # 保存 model 与 pool checkpoint
257            logger.show_pool_state()  # 打印池状态（每个因子 IC/表达式）
258            print(f"----Episode {episode}/{n_episodes} done----")
259            print(f"Current weights: SSL={current_ssl_weight:.4f}, Novelty={current_nov_weight:.4f}")
260            
261            # Log weight decay to tensorboard
262            logger.writer.add_scalar('weights/ssl_weight', current_ssl_weight, episode)
263            logger.writer.add_scalar('weights/nov_weight', current_nov_weight, episode)  # 记录当前权重到 TensorBoard，便于分析退火
264        
265        # Step the weight scheduler at the end of each episode
266        weight_scheduler.step()  # episode 末推进权重调度器一步

第 239 行 n_trajectories=1 是个重要选择。每步只采样 1 条轨迹，梯度极噪声大，所以第 247 行用 update_freq（默认 128）累积梯度再更新——等效于 batch_size=128 的小批量。这种「单步采样 + 梯度累积」比一次性采 128 条更省内存，也让 update_freq 可灵活调节。

第 238 行 save_estimator_outputs = args.entropy_coef > 0 与第 3 章呼应。熵正则需要每步的 logits，所以采样时要保存 estimator_outputs。不启用熵正则时关掉，省内存。这种「按需保存」让默认配置开销最小。

第 244 行 torch.isfinite(loss) 是数值稳定的关键防线。第 3 章的 loss 在 NaN 时返回 inf，这里检测到就跳过累计——inf 不会污染梯度（因为不参与 +=），但会被 minibatch_loss 跳过。配合第 247 行的 (episode+1) % update_freq == 0 and minibatch_loss != 0，保证只在有有效梯度时才更新。这种层层防御让训练能稳定跑完百万步。

第 254-263 行的日志与 checkpoint 是长训练的命脉。log_freq（默认 1000）每千步记录一次：池大小、最佳单因子 IC、测试集 IC/RankIC，以及当前退火权重。save_checkpoint 同时存 .pt 模型与 pool_*.json 池状态——后者直接喂给第 8 章的组合脚本。这种「训练产物即组合输入」的设计，让生成与组合无缝衔接。

设计权衡为什么用 PyTorch 调度器而非手写退火？因为 PyTorch 调度器经过充分测试，支持 linear/exponential/polynomial 多种曲线，且 get_last_lr() 接口稳定。代价是引入了 dummy Parameter 与 Optimizer（第 96-101 行），略显 hacky，但换来的代码简洁与正确性远超手写。这是「善用框架」的好例子。
小结WeightScheduler 复用 PyTorch 调度器实现 SSL/NOV 权重退火；train 主循环用「单步采样 + 梯度累积」模拟小批量，配合有限性检查保证稳定。checkpoint 同时存模型与池 JSON，无缝衔接第 8 章的组合。这是 AlphaSAGE 训练流程的完整工程实现。

关联公式

权重退火的一般形式：

$$\lambda(t) = \lambda_0 \cdot \text{scheduler}(t;\, \lambda_0, \lambda_T)$$

其中 $\lambda_T = \lambda_0 \cdot \text{final\_ratio}$。对应代码第 136 行 current_ssl_weight = initial_ssl_weight * ssl_lr。线性退火时 $\text{scheduler}(t) = 1 - (1-\text{final\_ratio}) \cdot t/T$。梯度累积的等效 batch size：

$$B_{\text{eff}} = \text{update\_freq} \times n_{\text{trajectories}}$$

默认 update_freq=128, n_trajectories=1，所以 $B_{\text{eff}}=128$。

小结

本章你看到了 AlphaSAGE 的训练全流程：WeightScheduler 退火权重，train 主循环采样、累积、更新、记录。梯度累积与有限性检查是稳定的基石，PyTorch 调度器复用是简洁的巧思。训练产出的 pool_*.json 直接进入下一章——动态组合。我们将看到这些候选 alpha 如何被滚动回归成 Mega-Alpha。
