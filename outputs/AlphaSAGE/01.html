第 1 章：数据与特征加载

StockData —— 把 Qlib 行情原料整理成张量，是整个 AlphaSAGE 的数据源头

欢迎

欢迎来到第 1 章！本章是整个教程的起点，我们会从最基础的数据加载讲起。量化研究中有一句话叫“Garbage in, garbage out”，如果输入数据质量不行，再尽心尽力的模型也无法挑救。AlphaSAGE 的一切都从 StockData 开始：它负责把 Qlib 的原始行情数据加载、清洗、重塑成为统一格式的张量，供下游表达式求值与模型训练使用。

我们会一步步进入 stock_data.py 的真实实现，看它如何与 Qlib 交互、如何处理时间窗口与前瞋天数，以及为什么要把数据重塑成 (n_days, n_features, n_stocks) 这样的三维张量。读完本章，你会明白 AlphaSAGE 数据流的第一站。

它解决什么问题？

类比来说，StockData 就像菜市场的进货清单：各种股票行情原料被按统一规格整理好供下游取用。

在量化研究中，我们面临一个常见难题：股票数据通常以“宽表”形式存储（每一行一个股票×一天×一个特征），但下游深度学习模型需要的是“块状”张量：一个轴是时间、一个轴是股票、一个轴是特征。同时，表达式如 TsMean($close, 20) 会引用过去 20 天的数据，因此需要预留 max_backtrack_days 天的缓冲；预测标签 Ref(close, -20) 需要未来 20 天，因此还需要 max_future_days 的前瞋区。这些看似琐碎的需求，被 StockData 统一封装成一个干净接口。

核心设计思路

StockData 的设计思路可以总结为三点：统一表达、统一张量、统一时间窗口。

统一表达：Qlib 原生接口要求传入字符串列表如 ['$close', '$open']，StockData 把内部的 FeatureType 枚举转成字符串，并支持 raw=True 时复原价（乘 $Factor）或复权成交易量（除以 /1000000），让上层不必关心复权细节。

统一张量：调用 df.stack().unstack(level=1) 把“股票×特征”的宽表转成以股票为列的 DataFrame，再 reshape 为 (n_days, n_features, n_stocks) 的 torch 张量。这个维度顺序与 PyTorch 卷积习惯一致，下游可以直接使用 Conv1d 或 Linear。

统一时间窗口：通过 max_backtrack_days 和 max_future_days 掩藏了“表达式需要的前置缓冲”与“标签需要的后置前瞋”，外部看到的 n_days 是净时间窗口，不会误用了未来信息，避免了 lookahead bias。

代码深入

类定义与构造函数

先看 StockData 类的骨架。它使用 FeatureType 枚举列出六种基本特征，构造时传入股票、时间范围与前后置窗口大小，然后立即调用 _get_data() 加载数据。

class FeatureType(IntEnum):
    OPEN = 0
    CLOSE = 1
    HIGH = 2
    LOW = 3
    VOLUME = 4
    VWAP = 5

FeatureType 继承 IntEnum，这样枚举值既可以当作索引使用，也可以与整型对比。下面的 change_to_raw 函数用于处理复权：价格类乘以 $Factor，成交量除以 $Factor 再除以 1000000（转换为百万手），让不同量级的数据在同一尺度下比较。

class StockData:
    _qlib_initialized: bool = False

    def __init__(self,
                 instrument: Union[str, List[str]],
                 start_time: str,
                 end_time: str,
                 max_backtrack_days: int = 100,
                 max_future_days: int = 30,
                 features: Optional[List[FeatureType]] = None,
                 device: torch.device = torch.device('cuda:0'),
                 raw:bool = False,
                 qlib_path:Union[str,Dict] = "",
                 freq:str = 'day',
                 ) -> None:
        self._init_qlib(qlib_path)
        self.df_bak = None
        self.raw = raw
        self._instrument = instrument
        self.max_backtrack_days = max_backtrack_days
        self.max_future_days = max_future_days
        self._start_time = start_time
        self._end_time = end_time
        self._features = features if features is not None else list(FeatureType)
        self.device = device
        self.freq = freq
        self.data, self._dates, self._stock_ids = self._get_data()

重点看构造函数的参数与最后一行。max_backtrack_days=100 表示预留 100 天的前置数据，足够支撑如 TsStd($close, 50) 这类需要 50 天回望的表达式；max_future_days=30 为预测标签预留 30 天前瞋。最后一行调用 _get_data()，该方法返回三元组 (data, dates, stock_ids)，其中 data 就是贴在 GPU 上的 torch 张量。

设计上有一个细节值得注意：构造函数中封装了 _init_qlib，该方法是 classmethod 且使用 _qlib_initialized 类变量保证 Qlib 只被初始化一次。多个 StockData 实例共享同一个 Qlib runtime，避免了重复加载数据目录导致的内存浪费。

_load_exprs：连接 Qlib 的桥梁

这个方法是 StockData 与 Qlib 之间的桥梁。它接收表达式列表，计算真实起止时间，调用 QlibDataLoader 加载。

    def _load_exprs(self, exprs: Union[str, List[str]]) -> pd.DataFrame:
        # This evaluates an expression on the data and returns the dataframe
        # It might throw on illegal expressions like "Ref(constant, dtime)"
        from qlib.data.dataset.loader import QlibDataLoader
        from qlib.data import D
        if not isinstance(exprs, list):
            exprs = [exprs]
        cal: np.ndarray = D.calendar(freq=self.freq)
        start_index = cal.searchsorted(pd.Timestamp(self._start_time))  # type: ignore
        end_index = cal.searchsorted(pd.Timestamp(self._end_time))  # type: ignore
        real_start_time = cal[start_index - self.max_backtrack_days]
        if cal[end_index] != pd.Timestamp(self._end_time):
            end_index -= 1
        real_end_time = cal[end_index + self.max_future_days]
        result =  (QlibDataLoader(config=exprs,freq=self.freq)  # type: ignore
                .load(self._instrument, real_start_time, real_end_time))
        return result

重点看几个关键点：

日历对齐：D.calendar(freq=self.freq) 获取 Qlib 的交易日历，searchsorted 找找到起止时间在日历中的位置。为什么不能直接用字符串时间？因为 Qlib 日历只含交易日，起止时间可能落在非交易日，需要 searchsorted 找到最近的交易日。

前后置窗口：real_start_time = cal[start_index - self.max_backtrack_days] 向前扩大加载范围，这部分数据不会暴露给下游，只是表达式求值的辅助缓冲。同理 real_end_time 向后扩大，为预测标签提供前瞋。

QlibDataLoader：这是 Qlib 提供的标准表达式求值器，传入 config=exprs 后会返回一个多层索引的 DataFrame。

_get_data：张量重塑的关键

这是整个类的核心。它调用 _load_exprs 拿到 DataFrame，然后用 stack/unstack 重塑并转 torch 张量。

    def _get_data(self) -> Tuple[torch.Tensor, pd.Index, pd.Index]:
        features = ['$' + f.name.lower() for f in self._features]
        if self.raw and self.freq == 'day':
            features = change_to_raw(features)
        elif self.raw:
            features = change_to_raw_min(features)
        df = self._load_exprs(features)
        self.df_bak = df
        # print(df)
        df = df.stack().unstack(level=1)
        dates = df.index.levels[0]                                      # type: ignore
        stock_ids = df.columns
        values = df.values
        values = values.reshape((-1, len(features), values.shape[-1]))  # type: ignore
        return torch.tensor(values, dtype=torch.float, device=self.device), dates, stock_ids

这段代码看似简单，却藏着一个重要的维度转换技巧。默认 QlibDataLoader 返回的 DataFrame 索引是 (date, stock) 的多层索引，列是各个特征。df.stack().unstack(level=1) 这个看似奇怪的操作其实是为了把列从“特征”转成“股票”，以股票为列之后才能 reshape 成 (n_days, n_features, n_stocks)。

最后一行 torch.tensor(values, dtype=torch.float, device=self.device) 把 numpy 数组转成了贴在 GPU 上的 torch 张量。这里有一个隐式假设：整个训练过程中特征张量一直驻留在 GPU 上，下游的表达式求值与 IC 计算都不会频繁跨 CPU/GPU 复制，这对训练速度至关重要。

属性与辅助接口

    @property
    def n_features(self) -> int:
        return len(self._features)

    @property
    def n_stocks(self) -> int:
        return self.data.shape[-1]

    @property
    def n_days(self) -> int:
        return self.data.shape[0] - self.max_backtrack_days - self.max_future_days

    def add_data(self,data:torch.Tensor,dates:pd.Index):
        data = data.to(self.device)
        self.data = torch.cat([self.data,data],dim=0)
        self._dates = pd.Index(self._dates.append(dates))

这些属性是外部访问数据形状的标准接口。n_days 的计算很妙：总天数减去前后置窗口，得到的是下游可用的净天数。这个值会被下游 make_dataframe 检查：如果传入的张量天数与 n_days 不匹配，会抛 ValueError。这是一个防御性检查，避免上下游天数不一致造成的难以调试的 bug。

数据流

数据流可以用一句话概括：Qlib 磁盘 → QlibDataLoader → DataFrame → stack/unstack → numpy → torch 张量（GPU）。

具体来说：用户传入 instrument='csi300', start_time='2010-01-01', end_time='2016-12-31'，StockData 调用 _get_data，后者调用 _load_exprs。_load_exprs 计算真实加载范围 [2009-某月, 2017-某月]（向前后各扩 100/30 天），调用 Qlib 返回原始 DataFrame。然后 _get_data 把 DataFrame 重塑为 torch 张量，返回给构造函数。这个张量会被 AlphaPoolGFN、QLibStockDataCalculator 和环境 GFNEnvCore 共享。

设计权衡

为什么选择 Qlib 作为数据底层？除了 Qlib 本身提供高性能的表达式求值与卷积操作（如 TsMean、TsStd）外，它还提供统一的数据格式与复权体系，这让 AlphaSAGE 不必重复造轮子。

为什么选择 (n_days, n_features, n_stocks) 而非 (n_days, n_stocks, n_features)？这与下游使用习惯相关。下游的 IC 计算、batch_pearsonr 都默认最后一维是股票，这样可以直接跨股票做点积、跨股票计算相关系数，与业界习惯一致。

为什么把前后置窗口隐藏在内部？因为如果让上层自己管理，很容易出现“忘记预留前置天数导致表达式越界”或“不小心用到了未来标签”这两类 bug。隐藏后，外部看到的 n_days 就是可以安全使用的净天数，不容易犯错。

小结

本章讲解了 AlphaSAGE 的数据底层：从 FeatureType 枚举到 _load_exprs 与 Qlib 交互，再到 _get_data 重塑为张量。这些看似基础的代码是整个框架运转的地基。
