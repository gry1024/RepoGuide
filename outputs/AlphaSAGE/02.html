第 2 章：表达式与算子体系

QLibStockDataCalculator 与算子词表 —— 连接语法与数值的桥梁

欢迎

欢迎来到第 2 章！上一章我们看到了 StockData 如何把行情数据加载成张量。但光有原始数据还不够，AlphaSAGE 要做的是自动挑挖 alpha —— 也就是能预测未来收益的表达式，比如 TsRank(Sub($close, Ref($close, -10)), 20)。要生成这样的表达式，首先得有一套算子词表和求值器。本章就来讲这两件事。

我们会读 config.py 看算子词表怎么定义，读 calculator.py 看表达式如何被求值成因子张量，还会看到“Mega-Alpha 的雏形”—— make_ensemble_alpha 如何把多个 alpha 加权融合。

它解决什么问题？

类比来说，这套表达式体系像搭积木的语法手册：规定了能拼出 alpha 公式的算子、特征与常数词表。

量化研究中的 alpha 挑挘问题，本质上是“在一个巨大的表达式空间中搜索优质表达式”。这个空间由三类词表定义：算子（如 Add、TsMean）、特征（如 $close）、常数（如 10）。如果词表太小，表达式空间不足以表达复杂策略；如果词表太大，搜索空间爆炸。需要谨慎选择。另外，表达式生成后还需要“求值”—— 把语法树转成实际的因子值，这就是 QLibStockDataCalculator 的工作。

核心设计思路

本章设计思路是词表与求值分离。词表在 config.py 集中定义，决定了生成器能走的“棋盘”；求值器在 calculator.py，使用 Qlib 的原生表达式 AST 求值能力，完全不重复造轮子。这样一来，修改词表不会影响求值逻辑，修改求值器也不会污染词表定义。

另一个重要设计是按日归一化。所有表达式求值后都会调用 normalize_by_day，把每一天的截面数据归一化到均值 0、方差 1。这样不同日期的因子值才可以公平比较，不会因为某一天整体波动大而主宰 IC 计算。

算子与特征词表

词表集中定义在 config.py，是生成器识别的“棋盘”。

# Action Space
OPERATORS = [

    # Pair rolling
    TsCov, TsCorr
]

FEATURES = [
    FeatureType.OPEN,
    FeatureType.CLOSE,
    FeatureType.HIGH,
    FeatureType.LOW,
    FeatureType.VOLUME,
    FeatureType.VWAP
]

DELTA_TIMES = [10, 20, 30, 40, 50]

CONSTANTS = [-30., -10., -5., -2., -1., -0.5, -0.01, 0.01, 0.5, 1., 2., 5., 10., 30.]

这里定义了四类算子：一元算子（如 Abs、Log）接收一个操作数；二元算子（如 Add、Sub）接收两个；滚动算子（如 TsMean、TsStd）需要一个特征加一个时间窗口；成对滚动算子（TsCov、TsCorr）需要两个特征加一个时间窗口。这个分类会在下一章 RGCN 中被用来定义六类边关系。

DELTA_TIMES = [10, 20, 30, 40, 50] 定义了五个滚动窗口。这里有一个权衡：窗口太多，生成器难以收敛；太少，表达力不足。五个窗口覆盖 10 到 50 天，是实践中常见的折中选择。CONSTANTS 里包含了从 -30 到 30 的 14 个常数，用于表达式中的静态偏置。

QLibStockDataCalculator 初始化与 _calc_alpha

class QLibStockDataCalculator(AlphaCalculator):
    def __init__(self, data: StockData, target: Optional[Expression]):
        self.data = data

        if target is None: # Combination-only mode
            self.target_value = None
        else:
            self.target_value = normalize_by_day(target.evaluate(self.data))

    def _calc_alpha(self, expr: Expression) -> Tensor:
        return normalize_by_day(expr.evaluate(self.data))

这个类继承了 AlphaCalculator，它是一个抽象基类。子类只需要实现 _calc_alpha 和几个 IC 计算方法即可。这是一个标准的模板方法模。

重点看 _calc_alpha：两行代码，却是整个计算器的核心。expr.evaluate(self.data) 是 AlphaSAGE 表达式框架的递归求值调用，返回一个 (n_days, n_stocks) 张量；normalize_by_day 则在每一天的截面上做归一化。这里有一个隐式约定：传入的 expr 必须能够在 self.data 的时间范围内求值，否则会抛 OutOfDataRangeError，这个错误会在环境 reward 中被 catch 并返回 0 奖励。

IC 与 ICIR 计算

    def _calc_IC(self, value1: Tensor, value2: Tensor) -> float:
        return batch_pearsonr(value1, value2).mean().item()
    
    def _calc_raw_IC(self, value1: Tensor, value2: Tensor) -> Tensor:
        return batch_pearsonr(value1, value2)
    
    def _calc_ICIR(self, value1: Tensor, value2: Tensor) -> float:
        aaa = batch_pearsonr(value1, value2)
        IC = aaa.mean().item()
        _std = aaa.std().item()
        return IC/_std

    def _calc_rIC(self, value1: Tensor, value2: Tensor) -> float:        
        return batch_spearmanr(value1, value2).mean().item()
    
    def _calc_raw_rIC(self, value1: Tensor, value2: Tensor) -> Tensor:
        return batch_spearmanr(value1, value2)
    
    def _calc_rICIR(self, value1: Tensor, value2: Tensor) -> float:
        # return batch_pearsonr(value1, value2).mean().item()
        aaa = batch_spearmanr(value1, value2)
        RIC = aaa.mean().item()
        _std = aaa.std().item()
        return RIC/_std

这些方法计算表达式与目标之间的相关性。IC（Information Coefficient）是正态化后的 Pearson 相关系数，衡量 alpha 与未来收益的线性相关程度。rIC（rank IC）则是 Spearman 相关系数，对极端值不敏感。

ICIR = IC 均值 / IC 标准差，这是一个关键指标。单纯高 IC 不够，还要 IC 稳定。如果 IC 时高时低，ICIR 会很低，表示该 alpha 不可靠。看 _calc_ICIR 的代码：先算每一天的 IC（返回 (n_days,) 张量），再取均值除以标准差。

这里有一个微妙之处：batch_pearsonr 是 PyTorch 实现，运行在 GPU 上，与上一章的数据加载保持一致。这让训练过程中的 IC 计算速度极快，不会成为瓶颈。

make_ensemble_alpha：Mega-Alpha 的雏形

    def make_ensemble_alpha(self, exprs: List[Expression], weights: List[float]) -> Tensor:
        n = len(exprs)
        factors: List[Tensor] = [self._calc_alpha(exprs[i]) * weights[i] for i in range(n)]
        return sum(factors)  # type: ignore

这个方法是第 8 章 Mega-Alpha 动态组合的雏形。传入表达式列表 exprs 和权重列表 weights，返回加权求和。

公式很简单：$$v_{ens} = \sum_i w_i v_i$$，其中 v_i 是第 i 个 alpha 归一化后的因子值，w_i 是其权重。这里的权重可以是固定的（如均等权重），也可以是第 8 章中由 OLS 回归得到的动态权重。

设计上的一个细节是：使用 list comprehension 而不是预分配张量再复制，这让 PyTorch 可以使用内存高效的递增操作。同时，调用 _calc_alpha 而不是直接 expr.evaluate，保证了每个子 alpha 都被归一化，不会因为量级不同而主宰加权融合结果。

数据流

数据流：Expression AST → expr.evaluate(data) → (n_days, n_stocks) 张量 → normalize_by_day → IC/ICIR 计算。

具体来说，上一章加载的 StockData 被传给 QLibStockDataCalculator，后者同时保持一个 target 表达式（预测未来 20 天收益）。调用 calc_single_IC_ret(expr) 时，会先求值得到因子张量，再与 target 张量计算 Pearson 相关系数。这个 IC 会被 Alpha 池使用（第 5 章）以决定是否入池，也会作为环境奖励的一部分（第 6 章）。

关联公式

$$v_{ens} = \sum_i w_i v_i$$

这是 make_ensemble_alpha 的数学表达，对应代码中的 sum(factors)。

设计权衡

为什么选择 Qlib 原生表达式 AST 而不自己实现求值？因为量化表达式求值需要高度优化的滚动窗口计算、卷积操作，重新实现极易出错且性能不佳。Qlib 提供的 AST 求值器已经被广泛验证，复用它可以节省大量工作。

为什么选择按日归一化而不是全局归一化？因为不同日期的市场波动幅度不同，全局归一化会让高波动日期的因子购买力过强，压制了低波动日期的信号。按日归一化让每一天内部处于同一尺度，互相比较公平。

为什么区分 IC 与 rIC？因为 Pearson 对极端值敏感，如果某一天有尊不同寻常的异常股票，IC 会被严重拉偏；而 Spearman 基于排名，对极端值稳健。两个指标互为补充，共同描绘 alpha 的预测能力。

小结

本章讲解了 AlphaSAGE 的表达式体系：从 config.py 的词表定义，到 calculator.py 的表达式求值与 IC 计算。我们看到了“Mega-Alpha 的雏形”—— make_ensemble_alpha 的加权融合逻辑。
