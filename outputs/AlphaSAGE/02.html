第2章：表达式与算子体系

像搭积木的语法手册，规定了能拼出 alpha 公式的算子、特征与常数词表。

欢迎

上一章我们拿到了干净的行情张量。但光有原始价量还不够——要生成有预测力的 alpha，必须能把它们组合成表达式，比如 TsMean($close, 20)` 或 `($high - $low) / $close。本章回答两个问题：我们能用哪些算子和词表？ 以及 表达式如何被求值成因子张量并算出 IC？

答案分别在 src/alpha_gfn/config.py 与 src/alphagen_qlib/calculator.py。前者定义了 GFlowNet 的动作空间（算子、特征、时间常数），后者把这些表达式算成数值并评估质量。两者合起来，就是 AlphaSAGE 的「表达式与算子体系」——一套可以被生成、可以被求值、可以被度量的 alpha 语法。

它解决什么问题？

因子挖掘的本质是在巨大的表达式空间里搜索。如果算子集合不固定、特征不枚举，搜索就成了无的放矢。config.py 把这个空间收束成一个有限的「词表」：30 多个算子、6 个特征、5 个时间窗口、14 个常数。GFlowNet 就在这个离散动作空间里一步步采样 token，拼出合法表达式。

但表达式本身只是语法树，要变成可比较的数值，需要求值器。QLibStockDataCalculator 承担这个角色：它把表达式喂给 StockData 求值，按日归一化，再与目标算 IC、ICIR。它还提供 make_ensemble_alpha——把多个 alpha 按权重加权融合，这正是后文「Mega-Alpha」组合的雏形。

核心设计思路

算子体系的设计遵循三条原则。第一，覆盖经典因子构造动作：一元（Abs、Log、Rank）、二元（Add、Sub、Mul、Div）、时序（TsMean、TsStd、TsCorr）、成对时序（TsCov、TsCorr），足以表达绝大多数技术因子。第二，离散化时间常数：窗口长度只在 [10,20,30,40,50] 里取，避免 GFlowNet 在连续值上浪费探索。第三，归一化前置：所有求值都过 normalize_by_day，让不同量级的因子在 IC 口径下可比。

QLibStockDataCalculator._calc_alpha —— 表达式到因子值

这是连接「语法」与「数值」的关键一环。任何表达式进来，都先 evaluate 成张量，再 normalize_by_day 归一化。它的简洁正说明设计之干净——所有复杂性都被 StockData 与 Expression 体系吸收了。

calculator.py第 20-51 行
20    def _calc_alpha(self, expr: Expression) -> Tensor:  # 求值核心：表达式 → 按日归一化后的因子张量
21        return normalize_by_day(expr.evaluate(self.data))  # normalize_by_day 消除横截面尺度差异，让 IC 可比
22
23    def _calc_IC(self, value1: Tensor, value2: Tensor) -> float:  # Pearson IC：线性相关性，最经典的 alpha 度量
24        return batch_pearsonr(value1, value2).mean().item()
25    
26    def _calc_raw_IC(self, value1: Tensor, value2: Tensor) -> Tensor:
27        return batch_pearsonr(value1, value2)
28    
29    def _calc_ICIR(self, value1: Tensor, value2: Tensor) -> float:  # ICIR = IC 均值 / IC 标准差，衡量 alpha 跨日稳定性
30        aaa = batch_pearsonr(value1, value2)  # 逐日算 Pearson IC 序列
31        IC = aaa.mean().item()
32        _std = aaa.std().item()
33        return IC/_std  # 均值除标准差，越大越稳定
34
35    def _calc_rIC(self, value1: Tensor, value2: Tensor) -> float:        
36        return batch_spearmanr(value1, value2).mean().item()
37    
38    def _calc_raw_rIC(self, value1: Tensor, value2: Tensor) -> Tensor:
39        return batch_spearmanr(value1, value2)
40    
41    def _calc_rICIR(self, value1: Tensor, value2: Tensor) -> float:
42        # return batch_pearsonr(value1, value2).mean().item()
43        aaa = batch_spearmanr(value1, value2)
44        RIC = aaa.mean().item()
45        _std = aaa.std().item()
46        return RIC/_std
47
48    def make_ensemble_alpha(self, exprs: List[Expression], weights: List[float]) -> Tensor:  # Mega-Alpha 雏形：按权重加权融合多个 alpha
49        n = len(exprs)
50        factors: List[Tensor] = [self._calc_alpha(exprs[i]) * weights[i] for i in range(n)]  # 每个 alpha 求值后乘以权重，逐项累加
51        return sum(factors)  # type: ignore  # sum 把列表合并成单一融合因子张量

第 29-33 行的 _calc_ICIR 是评估因子稳定性的核心。它不是简单算个平均 IC，而是看 IC 序列的「信噪比」：同样的平均 IC，如果某因子每天波动剧烈（标准差大），ICIR 就低，说明它不可持续；反之 ICIR 高的因子才值得入池。这也是为什么 AlphaSAGE 的奖励函数（第 6 章）以 IC 为主，但池管理（第 5 章）会用互相关做多样性筛选——单看 IC 不足以判断质量。

第 48-51 行的 make_ensemble_alpha 看似平淡，却是整个「Mega-Alpha」思想的起点。它把多个 alpha 按权重线性组合：权重好，组合就比任何单因子都稳。第 8 章会看到，run_adaptive_combination.py 把这个思想扩展成逐日滚动回归，用历史窗口数据动态求解最优权重——但底层求值，依然是这一行。

设计权衡为什么把 IC 与 ICIR 都实现出来？因为它们衡量的是不同维度：IC 看「能不能预测」，ICIR 看「预测稳不稳」。AlphaSAGE 的池管理用 IC 做入池门槛，而最终组合评估用 ICIR/Sharpe 衡量质量。分开实现让上层能按需取用，而不是被迫接受一个混合指标。
小结config.py 定义了 GFlowNet 的离散动作空间，calculator.py 把表达式求值成因子张量并算 IC/ICIR。两者构成「能生成、能求值、能度量」的闭环。make_ensemble_alpha 是 Mega-Alpha 组合的雏形，第 8 章会把它扩展成滚动回归。

关联公式

融合 alpha 的数学定义简单而关键：

$$v_{\text{ens}} = \sum_{i=1}^{n} w_i\, v_i$$

其中 $v_i$ 是第 $i$ 个按日归一化的因子，$w_i$ 是权重。代码里 make_ensemble_alpha 正是 $\sum_i w_i v_i$ 的直接实现。而 ICIR 的定义是：

$$\text{ICIR} = \frac{\overline{\text{IC}}}{\sigma_{\text{IC}}}$$

对应代码第 33 行 IC/_std。注意 calculator.py 还实现了 _calc_rICIR（基于 Spearman 秩相关），对极端值更稳健，这为第 9 章的评估指标体系埋下伏笔。

小结

本章你看到了 AlphaSAGE 的「语法手册」：config.py 划定算子与词表，calculator.py 负责求值与度量。理解了 _calc_alpha 的归一化与 make_ensemble_alpha 的加权融合，你就掌握了贯穿全仓库的两条主线——归一化保证可比，融合追求稳健。下一章将进入核心：GFlowNet 如何在这个动作空间里采样出多样化的表达式。
