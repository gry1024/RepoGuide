第4章：RGCN 结构编码器

像给公式做语法树体检，把算子当节点、按关系连边，再用图神经网络读出结构。

欢迎

GFlowNet 的策略网络要决定「下一步生成哪个 token」。如果只看序列（LSTM/Transformer），它会丢失表达式的语法结构——比如 Add($close, TsMean($high, 20)) 里，$close 和 TsMean(...) 都是 Add 的操作数，但序列模型看不到这种父子关系。AlphaSAGE 的解法是：把表达式的逆波兰式（RPN）转成关系图，用 RGCN 按六类边关系传递消息，提取结构感知的嵌入。

本章深入 src/alpha_gfn/modules.py 的两个关键函数：_build_graph_from_rpn（RPN 转图）和 GNNEncoder.forward（图卷积前向）。这是 AlphaSAGE 区别于普通序列 GFlowNet 的核心创新——它让策略真正「看懂」表达式结构。

它解决什么问题？

表达式天然是树（AST）。把树展平成序列会丢掉结构：同一个 token 在不同位置（是操作数还是算子？是左子还是右子？）语义完全不同。序列模型只能靠位置编码勉强区分，效果有限。

图神经网络则直接在 AST 上工作：算子是节点，操作数到算子是边。更进一步，AlphaSAGE 把边分成六类——一元操作数、可交换二元操作数、左操作数、右操作数、特征操作数、时序操作数——让 RGCN 能按关系类型分别聚合消息。这样 Sub 的左/右操作数不会被混淆，TsMean 的特征参数与窗口参数也能区分对待。

核心设计思路

RPN（逆波兰式）天然适合建图：遇到算子就从栈里弹操作数建边。设计上有三个要点。第一，边类型编码语义：六类边不是随意划分，而是对应算子的语义角色（左/右、特征/时序）。第二，RGCN 按关系分别变换：每种边类型有自己的权重矩阵 $W_r$，消息聚合时按类型加权。第三，全局平均池化：把节点级表示聚合成图级嵌入，供策略头使用。

代码深入

_build_graph_from_rpn —— RPN 序列转关系图

这个函数用经典栈算法遍历 RPN：遇操作数压栈，遇算子弹出操作数建边。关键在于根据算子类别分配 0-5 六种边类型。

modules.py第 13-71 行
13def _build_graph_from_rpn(token_ids: list[int], token_embedding_layer: nn.Embedding, beg_token_id: int) -> Data:  # 把 RPN token 序列转成 PyG 关系图 Data
14    device = token_embedding_layer.weight.device  # 获取设备，保证张量都在同一 GPU
15    tokens = []
16    for tid in token_ids:
17        if tid == beg_token_id:  # 起始符直接还原成 BEG_TOKEN
18            tokens.append(BEG_TOKEN)
19        else:
20            tokens.append(action2token(tid))
21    
22    edges = []  # 收集边 (操作数索引, 算子索引)
23    edge_types = []
24    stack = []
25    UNARY_OPS = ['Abs', 'SLog1p', 'Inv', 'Sign', 'Log', 'Rank']  # 一元算子：Abs/SLog1p/Inv/Sign/Log/Rank
26    COMMUTATIVE_OPS = ['Add', 'Mul']  # 可交换二元：Add/Mul（左右无序）
27    NON_COMMUTATIVE_OPS = ['Sub', 'Div', 'Pow', 'Greater', 'Less']  # 不可交换二元：Sub/Div/Pow/Greater/Less（左右有序）
28    ROLLING_OPS = ['Ref', 'TsMean', 'TsSum', 'TsStd', 'TsIr', 'TsMinMaxDiff', 'TsMaxDiff', 'TsMinDiff', 'TsVar', 'TsSkew', 'TsKurt', 'TsMax', 'TsMin',  # 时序算子：TsMean/TsSum 等
29        'TsMed', 'TsMad', 'TsRank', 'TsDelta', 'TsDiv', 'TsPctChange', 'TsWMA', 'TsEMA']
30    PAIR_ROLLING_OPS = ['TsCov', 'TsCorr']
31
32    for j, token in enumerate(tokens):  # 遍历每个 token，遇算子则从栈弹操作数建边
33        if isinstance(token, OperatorToken):
34            op = token.operator
35            n_args = op.n_args()  # n_args 决定弹几个操作数（一元1、二元2）
36            if len(stack) < n_args: continue
37            
38            for i in range(n_args):
39                child_node_idx = stack.pop()  # 弹出操作数索引，建 操作数→算子 的有向边
40                edges.append((child_node_idx, j))
41                
42                if op.__name__ in UNARY_OPS:  # 一元算子：边类型 0
43                    edge_types.append(0)  # Unary operand
44                elif op.__name__ in COMMUTATIVE_OPS:  # 可交换二元：边类型 1
45                    edge_types.append(1)  # Commutative binary operand
46                elif op.__name__ in NON_COMMUTATIVE_OPS:  # Non-commutative binary
47                    # The first pop (i=0) is the right-most operand in an expression
48                    if i == 0:  # 不可交换二元：右操作数=3，左操作数=2
49                        edge_types.append(3)  # Right operand
50                    else:
51                        edge_types.append(2)  # Left operand
52                elif op.__name__ in ROLLING_OPS or op.__name__ in PAIR_ROLLING_OPS:
53                    if i == 0:  # 时序/成对时序：时间参数=5，特征参数=4
54                        edge_types.append(5)  # Time series operand
55                    else:
56                        edge_types.append(4)  # Feature operand
57                else:
58                    raise TypeError(f"Unknown operator: {op.__name__}")
59        stack.append(j)  # 当前算子入栈，作为后续算子的潜在操作数
60
61    if not edges:
62        edge_index = torch.empty((2, 0), dtype=torch.long, device=device)
63        edge_type = torch.empty((0,), dtype=torch.long, device=device)
64    else:
65        edge_index = torch.tensor(edges, dtype=torch.long, device=device).t().contiguous()  # 边列表转置成 PyG 要求的 (2, num_edges) 形状
66        edge_type = torch.tensor(edge_types, dtype=torch.long, device=device)
67    
68    node_feature_ids = torch.tensor(token_ids, device=device)  # 用 Embedding 层把 token id 映射成节点特征向量
69    x = token_embedding_layer(node_feature_ids)
70    
71    return Data(x=x, edge_index=edge_index, edge_type=edge_type)

第 25-30 行的算子分类是整个图构建的灵魂。注意它把算子分成四类：一元、可交换二元、不可交换二元、时序。对不可交换二元（如 Sub），第 48-51 行用 i == 0 区分左右——栈是后进先出，所以 i=0 弹出的是表达式最右的操作数，标为类型 3（右），i=1 是左操作数，标为类型 2。这种区分让 RGCN 知道 Sub(A, B) 和 Sub(B, A) 是不同的结构。

第 52-56 行处理时序算子。TsMean($close, 20)` 里，`$close 是特征参数（类型 4），20 是时间参数（类型 5）。把它们区分开，让图卷积能用不同权重处理「被操作的特征」与「窗口长度」——这两者在语义上完全不同，混在一起会损失信息。

第 61-66 行处理空边情况（单个 token 的退化表达式），保证函数对边界输入不崩溃。第 68-69 行用共享的 token_embedding 层把 token id 映射成节点初始特征——这个 embedding 与策略网络共享，让图编码与策略输出对齐。

GNNEncoder.forward —— 多层 RGCN + 全局池化

编码器前向非常简洁：逐层 RGCNConv，每层按六类边分别聚合，最后全局平均池化成图级嵌入。简洁的背后是 RGCN 的强大表达力。

modules.py第 87-101 行
87class GNNEncoder(nn.Module):  # RGCN 编码器：多层关系图卷积 + 全局池化
88    def __init__(self, input_dim, hidden_dim, n_layers=2):
89        super().__init__()
90        self.num_relations = 6  # 0: unary, 1: commutative, 2: left, 3: right, 4: feature, 5: time series  # 六类关系：一元/可交换/左/右/特征/时序
91        self.layers = nn.ModuleList()
92        self.layers.append(RGCNConv(input_dim, hidden_dim, self.num_relations))  # 首层：input_dim → hidden_dim 的 RGCNConv
93        for _ in range(n_layers - 1):
94            self.layers.append(RGCNConv(hidden_dim, hidden_dim, self.num_relations))  # 后续层：hidden_dim → hidden_dim
95        
96    def forward(self, data: Batch):  # 前向：x/edge_index/edge_type/batch 四元组
97        x, edge_index, edge_type, batch = data.x, data.edge_index, data.edge_type, data.batch
98        for layer in self.layers:  # 逐层前向：每层按边类型分别聚合邻居
99            x = torch.relu(layer(x, edge_index, edge_type))  # ReLU 激活，引入非线性
100        
101        return global_mean_pool(x, batch)  # 全局平均池化：节点级表示聚合成图级表达式嵌入

第 98-99 行是 RGCN 的核心。每层 RGCNConv 对每个节点 $i$，按关系类型 $r$ 聚合邻居 $j \in N_r(i)$ 的消息：

$$h_i^{(l+1)} = \text{ReLU}\left(\sum_{r=0}^{5}\sum_{j \in N_r(i)} W_r^{(l)} h_j^{(l)}\right)$$

每种关系有独立的权重 $W_r$，所以「左操作数」和「右操作数」对算子节点的贡献可以不同。两层 RGCN 后，每个节点的表示已融合了两跳邻域的结构信息。

第 101 行 global_mean_pool 把所有节点表示平均成单一向量。这是「图级嵌入」——整条表达式的结构摘要。它会喂给策略头 （第 7 章的 pf_head）决定下一个 token，也会在第 6 章作为 SSL 奖励的「结构指纹」。一个池化操作，把变长的图变成定长向量，是后续所有下游任务的接口。

设计权衡为什么用 RGCN 而不是普通 GCN？普通 GCN 对所有边一视同仁，会把 Sub 的左右操作数混同。RGCN 按关系类型分别变换，能保留语义角色。代价是参数量随关系数线性增长——但这里只有 6 类关系，开销可控。另一个考量是计算图：RGCN 在稀疏 AST 上极快，比 Transformer 的注意力更高效。
小结_build_graph_from_rpn 用栈算法把 RPN 转成六类边的关系图，GNNEncoder 用两层 RGCNConv + 全局池化提取结构嵌入。这套「AST→图→嵌入」的管线，让策略网络真正感知表达式语法，是 AlphaSAGE 生成高质量、结构多样 alpha 的关键。

关联公式

RGCN 的消息传递公式（已展示）。它与代码的对应：$W_r^{(l)}$ 是 RGCNConv 内部的关系专属权重，$N_r(i)$ 由 edge_index 与 edge_type 共同定义，$\text{ReLU}$ 对应第 99 行。全局池化：

$$h_G = \frac{1}{|V|}\sum_{i \in V} h_i^{(L)}$$

对应第 101 行 global_mean_pool(x, batch)。这个 $h_G$ 既是策略输入，也是 SSL 奖励的结构指纹。

小结

本章你看到了 AlphaSAGE 的「结构感知」设计：把表达式 AST 转成六类边的关系图，用 RGCN 提取嵌入。这比序列模型更能捕获语法结构，也为第 6 章的 SSL 奖励提供了天然的结构指纹。下一章我们转向池管理——生成的 alpha 如何被筛选、入池、淘汰，形成可持续的候选库。
