第 4 章：RGCN 结构编码器

把 RPN 序列转成关系图，用 RGCNConv 读出表达式结构嵌入

欢迎

欢迎来到第 4 章！上一章我们看了 GFlowNet 如何生成多样 alpha 轨迹。但生成只是第一步，还需要让模型“看懂”表达式结构。为什么不用 LSTM 或 Transformer 处理 RPN 序列就够了？因为序列模型无法捕捉语法树中的父子、兄弟关系。比如 Sub($close, $open) 与 Sub($open, $close) 是不同的，参数顺序重要。RGCN 用关系图明确表达这些差异。

本章会进入 modules.py，看 _build_graph_from_rpn 如何把 RPN token 序列转成关系图，以及 GNNEncoder 如何用多层 RGCNConv 读出表达式的结构嵌入。

它解决什么问题？

类比来说，RGCN 编码器像给公式做语法树体检，把算子当节点、按关系连边，再用图神经网络读出结构。

alpha 表达式不是无规律的 token 序列，而是一棵有结构的语法树。例如 Add($close, Sub($open, $high)) 的 RPN 形式是 $close $open $high Sub Add。LSTM 处理它只看到顺序，看不到“Sub 操作了 $open 与 $high”这个结构信息。这导致两个语义不同的表达式在表征上差异不大。RGCN 通过为算子与操作数之间连边，让模型能“看见”语法结构。这是 AlphaSAGE 的核心创新之一。

核心设计思路

RGCN 编码器的设计思路是关系分类 + 多层消息传递 + 全局池化。

关系分类：不同类型的算子-操作数关系被赋予不同的边类型。AlphaSAGE 定义了 6 类关系：0=一元操作数、1=交换式二元操作数、2=非交换左操作数、3=非交换右操作数、4=特征操作数、5=时间序列操作数。这让 RGCN 可以区分 Sub(a, b) 与 Sub(b, a)，以及 TsMean($close, 20) 与 TsMean(20, $close)。

多层消息传递：多层 RGCNConv 让信息从叶子节点（特征/常数）流到根节点（算子），反之亦然，可以捕捉不同层次的语义信息。

全局池化：最后对所有节点嵌入取平均，得到表达式级别的嵌入。这个嵌入会被 SSL 奖励使用（第 6 章）来查近邻 alpha。

代码深入

_build_graph_from_rpn：RPN 到关系图

这个函数是 RGCN 的灵魂。它把 RPN token 序列转成带有边类型的 PyG Data 对象。

def _build_graph_from_rpn(token_ids: list[int], token_embedding_layer: nn.Embedding, beg_token_id: int) -> Data:
    device = token_embedding_layer.weight.device
    tokens = []
    for tid in token_ids:
        if tid == beg_token_id:
            tokens.append(BEG_TOKEN)
        else:
            tokens.append(action2token(tid))
    
    edges = []
    edge_types = []
    stack = []
    UNARY_OPS = ['Abs', 'SLog1p', 'Inv', 'Sign', 'Log', 'Rank']
    COMMUTATIVE_OPS = ['Add', 'Mul']
    NON_COMMUTATIVE_OPS = ['Sub', 'Div', 'Pow', 'Greater', 'Less']
    ROLLING_OPS = ['Ref', 'TsMean', 'TsSum', 'TsStd', 'TsIr', 'TsMinMaxDiff', 'TsMaxDiff', 'TsMinDiff', 'TsVar', 'TsSkew', 'TsKurt', 'TsMax', 'TsMin',
        'TsMed', 'TsMad', 'TsRank', 'TsDelta', 'TsDiv', 'TsPctChange', 'TsWMA', 'TsEMA']
    PAIR_ROLLING_OPS = ['TsCov', 'TsCorr']

    for j, token in enumerate(tokens):

第 25-30 行定义了四类算子。为什么要手动分类？因为不同类型的算子操作数顺序不同：一元算子只有一个操作数，交换式二元算子（Add/Mul）两个操作数等价，非交换二元算子（Sub/Div）顺序重要，滚动算子的两个操作数语义不同（一个特征、一个时间窗口）。这些区别需要被图编码器知道。

    for j, token in enumerate(tokens):
        if isinstance(token, OperatorToken):
            op = token.operator
            n_args = op.n_args()
            if len(stack) < n_args: continue
            
            for i in range(n_args):
                child_node_idx = stack.pop()
                edges.append((child_node_idx, j))
                
                if op.__name__ in UNARY_OPS:
                    edge_types.append(0)  # Unary operand
                elif op.__name__ in COMMUTATIVE_OPS:
                    edge_types.append(1)  # Commutative binary operand
                elif op.__name__ in NON_COMMUTATIVE_OPS:  # Non-commutative binary
                    # The first pop (i=0) is the right-most operand in an expression
                    if i == 0:
                        edge_types.append(3)  # Right operand
                    else:
                        edge_types.append(2)  # Left operand
                elif op.__name__ in ROLLING_OPS or op.__name__ in PAIR_ROLLING_OPS:
                    if i == 0:
                        edge_types.append(5)  # Time series operand
                    else:
                        edge_types.append(4)  # Feature operand
                else:
                    raise TypeError(f"Unknown operator: {op.__name__}")
        stack.append(j)

这是建图的核心逻辑。使用一个栈来跟踪待处理的操作数。遍历每个 token：如果是算子，从栈中 pop 出 n_args 个操作数，与算子节点连边；否则将 token 压栈（作为未来算子的操作数）。

边类型的赋值逻辑第 42-58 行：一元算子边类型 0；交换式二元算子 1；非交换二元算子的第一个 pop（i=0）是右操作数，赋类型 3，第二个是左操作数，赋类型 2；滚动算子的第一个 pop 是时间序列操作数（类型 5），第二个是特征操作数（类型 4）。

这里有一个隐藏的微妙之处：第一个 pop 是最右侧的操作数，这是 RPN 词法的一个重要特性。在 RPN 词法中，同一算子的操作数越后压栈的越在前面被 pop，因此 i=0 那个边是越右侧的操作数。正是因为区分了左右，RGCN 才能区分 Sub(a,b) 与 Sub(b,a)。


    if not edges:
        edge_index = torch.empty((2, 0), dtype=torch.long, device=device)
        edge_type = torch.empty((0,), dtype=torch.long, device=device)
    else:
        edge_index = torch.tensor(edges, dtype=torch.long, device=device).t().contiguous()
        edge_type = torch.tensor(edge_types, dtype=torch.long, device=device)
    
    node_feature_ids = torch.tensor(token_ids, device=device)
    x = token_embedding_layer(node_feature_ids)
    
    return Data(x=x, edge_index=edge_index, edge_type=edge_type)

这里极复杂的逻辑已经完成。最后构造 PyG 的 Data 对象，包含 x（节点嵌入）、edge_index（2×E 的边索引）、edge_type（边类型）。node_feature_ids 被 token_embedding_layer 查表得到嵌入，这个嵌入会在训练中被联合更新。

值得注意的是，当没有边时（只有单个 token 的退化情况），会返回空的 edge_index，避免 None 引发后续处理错误。

GNNEncoder：多层 RGCNConv

class GNNEncoder(nn.Module):
    def __init__(self, input_dim, hidden_dim, n_layers=2):
        super().__init__()
        self.num_relations = 6  # 0: unary, 1: commutative, 2: left, 3: right, 4: feature, 5: time series
        self.layers = nn.ModuleList()
        self.layers.append(RGCNConv(input_dim, hidden_dim, self.num_relations))
        for _ in range(n_layers - 1):
            self.layers.append(RGCNConv(hidden_dim, hidden_dim, self.num_relations))
        
    def forward(self, data: Batch):
        x, edge_index, edge_type, batch = data.x, data.edge_index, data.edge_type, data.batch
        for layer in self.layers:
            x = torch.relu(layer(x, edge_index, edge_type))
        
        return global_mean_pool(x, batch)

GNNEncoder 是 RGCN 的前向逻辑。构造时创建 n_layers 层 RGCNConv，第一层从 input_dim 到 hidden_dim，后续层从 hidden_dim 到 hidden_dim。

forward 方法的逻辑很简单：逐层调用 RGCNConv，每层后加 ReLU 激活。最后调用 global_mean_pool 对所有节点嵌入取平均，得到一个固定长度（hidden_dim）的向量作为表达式嵌入。

这里的 global_mean_pool 使用 batch 参数区分不同图的节点，支持多个表达式同时编码（batch 处理）。RGCNConv 的核心公式：$$h_i^{(l+1)} = \text{ReLU}\left(\sum_{r}\sum_{j\in N_r(i)} W_r^{(l)} h_j^{(l)}\right)$$，其中 r 遍历 6 种关系类型，N_r(i) 是节点 i 在关系 r 下的邻居，W_r 是该关系专属的变换矩阵。

数据流

数据流：RPN token 序列 → _build_graph_from_rpn 建图 → token_embedding 查表 → 多层 RGCNConv → global_mean_pool → 表达式嵌入。

具体来说，环境（第 6 章）采样到一条 alpha 表达式后，会调用 SequenceEncoder.forward(state_tokens)。如果 encoder_type='gnn'，会对每个 batch 调用 _build_graph_from_rpn 建图，用 Batch.from_data_list 拼接，最后调用 GNNEncoder 前向。输出的嵌入会被 pf_head 转成每个 token 的 logit，作为 GFlowNet 的前向策略。

关联公式

$$h_i^{(l+1)} = \text{ReLU}\left(\sum_{r}\sum_{j\in N_r(i)} W_r^{(l)} h_j^{(l)}\right)$$

这是 RGCN 的核心更新公式，对应代码中的 layer(x, edge_index, edge_type)。对每种关系 r 有一个专属的变换矩阵 W_r，避免不同关系的信息被混合。

设计权衡

为什么选择 RGCN 而不是普通 GCN？普通 GCN 所有边共享一个变换矩阵，无法区分不同关系。RGCN 为每种关系学习专属的 W_r，能捕捉语法结构。对于 alpha 表达式这种强结构化输入，是合适的选择。

为什么用全局平均池化而不是取 [CLS] 节点？全局平均对所有节点一视同仁，不需要额外训练一个“汇总节点”。对于不同长度的表达式，它都能输出固定维度的嵌入。

为什么不加残差连接？AlphaSAGE 使用的 RPN 序列本质是树结构，不需要像序列模型那样使用残差连接捕捉位置信息。边的类型已经表达了充分的结构信息。

小结

本章讲解了 RGCN 结构编码器：从 _build_graph_from_rpn 将 RPN 转成关系图，到 GNNEncoder 用多层 RGCNConv 读出表达式嵌入。六类关系边让模型能区分算子与操作数的类型与顺序。
